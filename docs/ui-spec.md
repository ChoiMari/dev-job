\# DevJob UI Specification

## 프론트 전면 개편 예정: 로그인 전 공개 홈

비로그인 첫 접속의 `#/`은 공개 홈으로, 로그인 후 `#/`은 기존 대시보드로 사용한다. 공개 홈은 실제 기능 소개와 로그인·회원가입 이동을 제공하며 사용자별 수치·임의 공고를 표시하지 않는다. 세션 확인 중 화면을 먼저 노출하지 않고, `401` 외의 확인 오류는 재시도로 안내한다. 기존 보호 경로에 미인증으로 직접 진입하면 로그인으로 이동한다. 화면 구성·검증 기준은 [프론트 요구사항 FR-P00](frontend-redesign-requirements.md#3-페이지별-요구사항)과 [실행 계획 F01~F02](frontend-redesign-implementation-plan.md#3-의존성-그래프와-실행-단계)를 따른다. 아래 2026-10-07 절은 당시 구현 기록이다.

F01 구현: `#/`의 미인증 상태에는 소개·기능 안내·로그인/회원가입 CTA만 있는 공개 홈 뼈대를 표시한다. 인증 성공에는 기존 대시보드, 확인 중에는 로딩, 401 이외 조회 실패에는 재시도를 표시한다. 다른 보호 경로는 미인증일 때 `#/login`으로 이동한다. 공개 홈 전용 이미지와 최종 화면 디자인은 F02에서 처리한다. 공통 Sidebar/상태 스타일은 F01에서 정리했으며 아래 과거 화면 캡처·검증 수치는 F01의 검증 결과가 아니다.

공개 홈 후속 디자인: 로그인·회원가입 이동은 상단 메뉴에 유지하고 히어로의 중복 버튼은 제거했다. 여성 개발자가 뒷모습으로 작업하는 픽셀 아트 장면과 함께 공고 탐색→지원 관리→역량 성장 흐름, 문서 버전·분석·추천의 실제 제공 기능을 설명한다. 장식 이미지가 실패해도 소개 문구와 상단 인증 이동은 유지한다.

인증 후 공통 화면 후속 디자인: Header는 `brand-devjob-wordmark-dark.png` 로고와 계정 정보·로그아웃을 표시하고 중복된 현재 화면 제목은 표시하지 않는다. Sidebar에는 메뉴 링크만 표시하고 `시작하기`·`나의 취업 준비`·`인사이트` 그룹 제목을 숨긴다. 어두운 단색 Sidebar 배경을 유지한다. Header 아바타와 Sidebar 하단은 `GET /api/me/character`의 장착 의상·헤어·안경 상태로 완성 이미지를 선택하고, Sidebar에는 실제 레벨·EXP를 표시한다. 캐릭터 조회 실패 시 프로필 아이콘과 캐릭터 페이지 링크를 표시한다. 장착·보상 변경 직후에는 화면에 반영한다. 대시보드는 장면 이미지와 실제 API 데이터 기반 현황·행동·공고를 함께 표시하며, 보조 픽셀 이미지는 장식으로만 사용한다.

대시보드 후속 수정: 상단 장면은 개발 중인 여성의 뒷모습을 보여주는 새 픽셀 이미지로 교체하고, 기존 인사 문구·CTA 대신 4개 집계를 표시한다. `진행 중인 지원`은 `APPLIED`·`DOCUMENT_PASSED`·`INTERVIEW`, `완료한 지원`은 `FINAL_PASSED`·`REJECTED`·`WITHDRAWN`의 `GET /api/dashboard.applicationCounts` 합계다. `관심 공고`는 같은 응답의 `bookmarkCount`(수집 공고 북마크와 개인 저장 공고의 합계)다. `관심 기업`은 `GET /api/me/companies?page=0&size=20`의 `totalElements`로, 보관 상태도 포함하는 등록 기업 전체다. 기업 조회 실패·진행 중에는 임의의 0을 표시하지 않고 `—`를 표시한다. 바로가기 3개는 별도 생성한 단순한 픽셀 이미지로 표시한다. Header 아바타는 장착 캐릭터의 얼굴, Sidebar 하단은 얼굴과 상반신이 보이도록 자른다. 이 작은 영역에서는 원본을 68/78px 너비로 직접 렌더링하고 넘친 부분을 잘라 화질 저하를 줄인다. 토끼 의상은 귀와 얼굴이 함께 보이도록 Header·Sidebar 각각 44/64px 너비로 표시한다. Sidebar 하단은 군더더기 문구 없이 레벨과 EXP만 보여준다. 이 값은 `GET /api/me/character.progress` 응답이며 프론트에서 임의 생성하지 않는다.

## 2026-10-07 프론트 화면 구성

- 인증 후 `#/`을 시작 화면으로 사용하고 Header, 그룹화된 Sidebar, 화면별 제목을 공통으로 적용한다. `#/jobs` → 공고 상세 → 관심 저장·지원 예정·AI 분석/역량 비교, `#/applications` → 지원 상세·상태/일정/메모, `#/profile` → 기술, `#/projects`, `#/learning-goals`, `#/analytics/skills`로 이동할 수 있다.
- 대시보드는 이미지가 있는 안내 배너, API 기반 4개 현황, 준비 단계 바로가기, 다음 행동, 추천 공고, 부족 기술 미리보기로 구성한다. 이미지는 정보나 수치를 대신하지 않으며 [Frontend 에셋 지도](frontend-asset-map.md)에 기록한다.
- UI-010 `#/character`는 캐릭터 꾸미기와 활동·보상 화면을 제공한다. UI-011 `#/settings`는 알림 설정·비밀번호 변경·계정 관리의 3개 탭을 제공한다. 알림 설정은 채용공고·분석 결과·기타·일정 그룹의 사용자별 Boolean 값을 변경 즉시 저장한다. 기존 면접/할 일 알림과 새 공고·기술 기반 맞춤 공고·관심 공고 변경·문서 분석·공고 기술 분석·의미 기반 비교·학습 목표·캐릭터 활동·서비스 공지를 앱 내 목록에 생성한다. 기술 기반 맞춤 공고는 대시보드의 보유 기술 일치 추천과 같은 데이터에 기반하며 UI에서는 `AI` 명칭을 쓰지 않는다. 알림 설정에는 별도의 알림 목록 링크를 표시하지 않는다. 비밀번호 변경 성공 시 로그아웃하고, 계정 관리는 현재 계정 이메일과 삭제 영향 조회·재인증 후 삭제 흐름을 제공한다. 삭제 영향은 안내 배너, API 응답의 전체 기록 항목·건수 카드, 복구 불가 경고, 비밀번호·확인 문구 입력 영역으로 표시한다. 설정 탭과 비밀번호 변경 버튼은 채용공고 화면의 보라색 강조색을 사용한다.
- 계정 관리의 별도 `삭제 영향 보기` 버튼은 표시하지 않는다. `계정 삭제하기`로 영향 목록과 재인증 영역을 열며, 상세에서는 하단 취소 버튼으로 닫는다. 현재 계정 이메일 위에는 별도 구분선을 두지 않는다.
- 작은 화면에서는 Sidebar를 접고 배너·카드·입력 열을 세로 배치한다. 모든 장식 이미지에는 대체 설명을 비우고 실제 내용은 텍스트와 입력 요소로 제공한다.

## 면접 일정 목록 후속 디자인

목록형의 다가오는 면접 일정은 외곽 테두리 없이 위아래 점선으로 구분한다.

면접 일정의 취소 아이콘을 누르면 브라우저 기본 확인창 대신 제목·되돌리기 안내·취소/확인 버튼이 있는 앱 확인 모달을 표시한다. 확인 전에는 일정을 변경하지 않는다.

면접 일정의 날짜·시간은 저장된 시간대를 기준으로 계산하되 목록·달력의 선택 날짜 카드·상태 변경 시각에는 `Asia/Seoul` 같은 시간대 식별자를 표시하지 않는다.

면접 상세 모달의 하단 동작 버튼은 위치를 유지하며 작은 크기로 표시한다. 지원 상세 모달의 진행 상태·지원일·지역·다음 확인 일정 칸에는 내부 구분선을 두지 않는다.

지원 상세 모달의 수정·삭제 버튼은 머리말에서 본문 오른쪽 아래로 옮기고, 닫기 버튼은 머리말 오른쪽에 유지한다.

면접 상세 모달은 지원 상세처럼 좁은 카드형 크기와 픽셀 달력 이미지·제목·설명·닫기 버튼이 있는 머리말로 표시한다. 별도 뒤로 버튼과 장식 배너를 두지 않고, 완료·취소·수정 성공 안내 박스도 모달에서 표시하지 않는다. 상태 배지와 상세 제목은 작은 크기로 한 줄에 자연스럽게 배치하며, 상세 정보와 머리말 사이에 구분선은 두지 않는다. 상세 동작 버튼은 기존 하단 위치를 유지하고 예정으로 되돌리기 버튼은 주요 동작의 보라색을 사용한다.

면접 일정 등록을 저장하면 `#/interviews?detail={id}`의 목록으로 돌아와 등록한 일정의 상세 모달을 연다. 모달을 닫으면 목록 주소로 돌아온다. 면접 상세 모달에서 수정 버튼을 누르면 `#/interviews/{id}?edit=1` 전체 페이지의 수정 폼으로 이동한다. 해당 페이지에서 저장하거나 취소하면 상세 주소로 돌아온다.

면접 일정 목록 `#/interviews`는 공통 중복 페이지 제목을 숨기고 작은 픽셀 달력 이미지·제목·설명을 한 카드에 표시한다. 전체·이번 달·예정·완료 수치는 기존 면접 응답으로 계산하며, 예정은 파란 시계 아이콘, 완료는 초록 체크 아이콘으로 구분한다. 달력형·목록형 전환은 아이콘 버튼과 접근 가능한 이름으로 제공하고, 월 이동 묶음·오늘을 보기 전환 아이콘 바로 옆에 두며 등록 버튼은 오른쪽에 둔다. 일정 제목·상세 링크를 누르면 목록을 유지한 채 기존 상세 화면을 모달로 열고, 모달 안에서 수정·완료·취소한 결과를 목록에 반영한다. 상세 주소 직접 진입도 유지한다. 선택 날짜에 일정이 없으면 픽셀 고양이·달력 그림과 안내만 보여준다. 목록형 빈 결과에는 별도의 픽셀 고양이·달력 이미지와 전체 없음·해당 월 없음·검색/필터 결과 없음에 맞는 문구를 표시한다. 배경·테두리·버튼 색은 채용공고·관심 공고와 같은 남색·보라 계열을 쓴다.

면접 일정 등록 `#/interviews/new`와 수정 화면은 기존 배치와 장식 배너를 유지하고, 기본 정보 제목은 생략한다. 입력 폼 전체는 얇은 사각형 테두리로 구분한다. 제목·설명·선택·취소·저장 버튼의 글자와 배경색을 채용공고·관심 공고의 남색·보라 계열에 맞춘다. 목록의 상세 이동 버튼은 `일정 상세`로 표시한다. 면접 일정 상세는 장식 배너를 유지하고, 일정·연결된 지원의 회사와 공고명·값이 있는 면접 단계·방식·메모를 카드로 표시한다. 연결된 지원 정보 조회에 실패해도 지원 상세 링크는 제공한다.

## B03 개인 할 일 Frontend

할 일 목록의 알림 여부는 기한 바로 옆에 작은 선형 벨 아이콘으로 표시하고, 완료된 할 일에서는 아이콘을 회색으로 표시한다. 전체 할 일 카드의 제목 아래에는 점선 구분선을 두고, 검색·정렬 영역과 첫 할 일 사이의 구분선은 없앤다.

선택 날짜에 할 일이 없을 때는 그림과 안내를 선택 날짜 카드의 남는 높이 가운데에 배치한다.

할 일 상세의 삭제 버튼은 상세 내용 아래에 확인 문구를 펼치지 않고, 삭제 안내와 취소·삭제 버튼이 있는 별도 확인 모달을 연다. 확인 모달에는 할 일 제목을 반복하지 않는다. 확인 전에는 삭제하지 않는다. 상세에서 저장·완료·완료 취소 후 성공 안내 박스는 표시하지 않고 갱신된 내용을 바로 보여준다.

- Sidebar `내 할 일`에서 `#/todos` 월·주·일 달력과 선택 날짜 할 일을 나란히 표시하고 그 아래 전체 목록을 표시하며, `#/todos/new`는 목록 위 등록 모달로 연다. `#/todos/{id}`에서 상세 모달과 그 안의 수정·완료 취소·삭제 확인을 제공한다. 상세에는 제목 아래 설명을 놓고 날짜·마감 시각·설정된 알림을 작은 정보 태그로 표시하며, 상태와 카테고리도 유지하고 시간대 이름은 반복하지 않는다. 달력은 기존 목록 API의 모든 페이지를 읽어 기기 시간대 기준 기한 날짜에 점으로 배치한다. 달력 오른쪽에는 선택 날짜의 할 일을, 그 아래 전체 목록에는 기한 없는 항목을 포함한 모든 할 일을 표시한다. 전체 할 일 목록은 제목 아래 전체·진행 중·완료 탭과 실제 할 일에 쓰인 카테고리 태그·더보기를 놓고, 그 아래 제목·내용 검색과 최신순·기한순 정렬을 제공한다. 각 행에서는 알림을 메뉴 앞에 두고, 메뉴에서 수정·삭제할 수 있다. 메뉴를 열면 행 높이를 바꾸지 않고 목록 위에 겹쳐 표시하며 수정·삭제 항목의 아이콘과 텍스트를 같은 시작점에 정렬한다. 선택 날짜 카드와 전체 목록 카드의 상단 오른쪽에 작은 테두리형 `＋` 추가 버튼을 표시한다. 등록 모달은 오늘 날짜·알림 없음으로 시작하고 기한 없음, 선택 시간, 메모, 알림 시간을 받는다. 시간을 선택하지 않으면 23:59와 Asia/Seoul 안내를 유지한다. 등록 모달의 카테고리 추가 버튼은 바로 추가 모달을 열고 관리 버튼은 관리 모달을 열어 최대 20개를 이름·아이콘·색상으로 관리하며 드래그 정렬·수정·삭제를 제공한다. 참고 이미지의 작은 픽셀 아이콘 스타일로 각각 생성한 28개 독립 PNG를 카테고리 아이콘 선택창에 7열 4행으로 표시한다. 작은 태그에서도 같은 개별 아이콘을 재사용하고, 등록 모달의 카테고리 선택 버튼과 관리 목록에서는 이미지를 더 크게 부드럽게 표시한다. 카테고리 이름 입력 포커스는 파스텔 하늘색이며 추가창 왼쪽 아래에서 카테고리 관리를 연다. 대시보드 카테고리 필터의 전체 선택은 `All`로 표시한다. 대시보드와 할 일 등록·카테고리 추가·관리·상세 모달 버튼의 기본·선택·호버·키보드 포커스 색은 채용공고 화면의 보라색 계열로 맞추고, 카테고리 자체 색상과 삭제 동작의 위험 색상은 유지한다. 선택 날짜와 전체 목록 행의 작은 카테고리 이미지를 더 크게 부드럽게 표시한다. 할 일 행의 메뉴와 알림은 한 줄에 배치하며 완료 시 제목과 기한에 취소선을 표시한다. 알 수 없는 아이콘 키는 `puzzle` 아이콘으로 표시한다. 완료한 항목은 취소선으로 구분하고 체크박스 변경 성공 시 서버 응답으로 갱신한다. 수치와 일정은 조회 응답에서 계산하며 로딩·오류 중 임의 수치를 표시하지 않는다. 대시보드의 `personalTodos`는 별도 미완료 미리보기로 보여주며 기존 지원 기록 기반 `nextActions`와 제목·링크를 구분한다.
- 상태 탭의 `진행 중`은 미완료 항목, `완료`는 완료 항목만 표시한다. 달력에는 목록 필터와 무관하게 실제 기한 날짜의 점을 표시한다.
- 머리말은 작은 할 일 아이콘·제목·설명·`할 일 추가` 버튼으로 구성한다. 선택 날짜가 비면 별도의 고양이·달력 픽셀 이미지를 표시하며 이미지는 장식이고 실제 완료 상태는 목록과 탭 수치로 전달한다. 이미지 시안은 사용자 확인 후 연결한다.
- 기한은 기기 시간대에서 입력하고 저장된 시간대 이름을 상세·목록에 표시한다. 로딩·빈 상태·오류 재시도, 변경 중 중복 방지, 저장 후 재조회, 삭제 취소는 [확장 UI-E03](extension-ui-spec.md#ui-e03-개인-할-일--ext-03)을 따른다.

## S06 프로젝트 관리 구현

- 보호된 `#/projects`에서 내 프로젝트 목록·생성 순서·기술 배지·20건 페이지 이동·빈 상태·로딩·오류 재시도를 제공한다. `#/projects/new`에서 프로젝트명·시작일과 선택 설명·종료일·역할·주요 기능·성과·URL을 입력한다.
- 표준 기술·별칭 검색의 페이지 목록에서 기술을 선택/해제하고 프로젝트 저장 시 `skillIds`를 전송한다. 빈 선택도 허용하며 보유 기술 API를 호출하지 않는다. 검색 실패는 재시도할 수 있고 기존 선택·폼 입력을 유지한다.
- `#/projects/{projectId}`에서 서버 저장값을 조회한다. 등록 후 상세로 이동하고 수정 성공 후 응답을 표시하며 수정 취소는 저장값을 복원한다. 종료일 null은 `진행 중`, 없는 선택 정보는 `정보 없음`으로 표시한다. 설명은 HTML을 실행하지 않는 줄바꿈 보존 텍스트, URL은 http/https 새 창 링크다.
- 저장·삭제 중 중복 제출을 막고 실패 시 입력을 유지한다. 삭제는 화면 내 확인/취소를 거쳐 목록으로 이동한다. 상세 조회 실패 재시도, 403·404 안내, 잘못된 ID 경로 안내와 목록 복귀를 제공한다.
- S02-V의 Badge·공통 상태·색상·포커스·44px 조작 기준을 재사용하고 CSS는 `pages/projects/projects.css`에 둔다. 날짜 입력은 Desktop 2열·Mobile 1열이다. App·Layout에 프로젝트 경로와 메뉴만 연결한다.

## S08 구현 화면·통합 경계

- `#/jobs`: 제목·회사 검색, 회사·지역·경력·고용 형태·마감일 이전·출처 입력, 최신순·마감 임박순, 페이지당 20/50/100건과 검색·초기화. 결과에는 출처 배지·회사·제목 링크·기본 조건과 전체 건수·페이지를 표시한다. 경력·고용 형태는 저장값 정확 일치 안내를 제공한다.
- 공고 탐색의 현재 UI는 항상 보이는 키워드 검색창과 별도 상세 필터를 결과 위에 두고, 상세 필터는 기본으로 접어 둔다. 상세 필터는 화살표 아이콘으로 열고 닫으며 키워드를 제외한 상세 조건의 적용 수만 표시하고, 초기화 아이콘은 펼쳤을 때 상세 필터 제목줄에 둔다. 키워드, 단일 직무, 경력 구간, 클릭식 단일 고용 형태, 전국 시도 콤보박스, 마감일 빠른 선택, 단일 기술, 최소 기술 일치도를 표시한다. 경력은 신입·경력무관·1년 이하·1~3년·3~5년·5년 이상 중 여러 개를 체크할 수 있고 `careerBands`로 한 번에 보내 OR 검색한다. 원천 공고의 경력 문구가 구간 판별에 부족하면 해당 공고는 제외될 수 있다. 고용 형태는 저장값 정확 일치 선택지다. 마감일의 오늘/3일/7일/30일 선택은 `deadlineBefore` 날짜로 변환하고 날짜 입력란은 표시하지 않는다. 최소 기술 일치도는 사용자 기술과 완료된 공고 AI 분석으로 계산된 공고에만 적용된다는 안내를 표시한다. 전체 저장 공고를 기본으로 조회하며 검색 시 `GET /api/jobs` 조건과 URL 쿼리를 사용하고 첫 페이지로 돌아간다. 이전 URL의 회사·출처·IT 범위·지원 상태·정렬·페이지 크기·기존 `careerLevel` 조건은 직접 진입 시 유지하고 화면에 적용 안내를 표시하며, 초기화나 새 검색 시 해제한다. 학력과 여러 직무의 OR 검색은 현재 API가 지원하지 않아 제공하지 않는다. 공고 탐색 이미지는 결과 카드 머리말의 작은 장식으로 유지하고 큰 내부 배너는 사용하지 않는다. 의미 기반 비교 이동은 이 화면에서 제거한다. 페이지 제목·검색창·상세 필터·결과 카드·페이지 이동 버튼의 색상과 테두리·간격은 공고 상세의 남색 글자·연보라 배경·보라 강조 팔레트에 맞춘다.
- `#/jobs/{jobId}`: 픽셀 도시·기존 고양이 배너에 글자 가독성용 밝은 그라데이션을 적용하고, 목록 복귀, 회사·제목·출처·지역·경력·고용 형태·게시/마감일 요약을 표시한다. 요약 오른쪽에는 테두리 없는 관심 저장 아이콘만 두고, 외부 출처 링크는 상세 내용 머리말에 둔다. 상세 내용·지원 현황만 탭으로 전환한다. AI 분석은 우측 카드에서 기존 분석 요청·상태·결과를 바로 표시하고, 완료 상태·기술 그룹·빈 결과·기술 태그를 상세 카드의 보라·초록 계열 크기와 간격에 맞춘다. 내 기술 매칭은 AI 분석 완료 후 카드에서 추출된 공고 기술과 등록한 보유·프로젝트 기술을 비교한다고 안내하고, `기술 비교하기`로 기존 비교 결과를 표시한다. 좁은 화면에서는 카드가 상세 내용 아래에 쌓인다. 지원 기록이 없을 때는 지원 현황 탭 안에 지원 관리 추가 모달과 동일한 7개 상태 선택·지원일 조건·일정·메모 등록 폼을 표시한다. 지원 기록을 저장하면 요약 상태와 지원 현황 탭을 갱신한다. 지원 현황 탭은 공고별 내 지원 조회 응답의 현재 상태·값이 있는 지원일·다음 확인 일정·메모만 카드별로 표시하고, `지원 상세 보기`로 지원 관리 모달에 연결한다. 탭에 들어갈 때 지원 상태를 다시 조회해 공고 요약도 갱신한다. 기업 카드는 기존 응답의 회사명·출처·공고 근무 정보만 표시하며 업종·규모·조회수처럼 제공되지 않는 값은 만들지 않는다. 본문은 HTML을 실행하지 않고 텍스트로 표시하며 줄바꿈을 보존한다. 없는 기본 필드는 표시하지 않고 본문 null은 외부 출처 안내로 표시한다.
- 지원 상태 배지는 공고 상세·관심 공고·공고 목록·지원 상세에서 같은 픽셀 이미지와 상태명 텍스트를 사용한다. 이미지 순서는 지원 예정·서류 접수·서류 합격·면접·최종 합격·불합격·철회다.
- 청년일자리 출처의 상세에는 제공된 전형 단계와 첨부파일 메타정보를 별도 구역에 표시한다. 첨부파일은 검증된 HTTP(S) URL로 새 창에서 열고, 비어 있으면 각각 빈 상태 문구를 표시한다. 다른 출처에는 이 구역을 표시하지 않는다.
- 공고 목록은 DB의 저장 공고만 조회하고 외부 API 수집 과정과 제공기관 페이지·요청 파라미터를 표시하지 않는다. 출처 선택은 전체·공공기관(`ALIO_RECRUITMENT`)·고용24(`WORK24_OPEN_RECRUITMENT`)를 제공하고 다른 검색·필터·정렬·페이지 조건과 함께 적용한다. 저장 공고 목록은 IT 직무 제목 필터를 기본 선택하고 전체 저장 공고로 전환할 수 있다. ALIO 배지는 `공공기관 채용`으로 표시하고 제공된 `srcUrl`은 공고 원문이 아닌 기관 홈페이지일 수 있으므로 `제공된 출처 사이트 열기`로 안내한다.
- 제목 기반 직무 필터는 개발·데이터/AI·보안·클라우드/인프라·전산/IT 운영·기타를 제공한다. 기타는 앞의 다섯 직무 제목 키워드에 해당하지 않는 공고이며, 일반 목록과 기술 일치도 정렬 목록에 같은 조건을 적용한다. 필터 아래의 기타 설명 문구는 표시하지 않는다. `개발`처럼 짧은 검색어는 제목·회사만 검색하고 3자 이상은 저장된 본문도 검색한다. 카드·상세에 직무를 표시한다. 상세의 AI 분석 버튼은 항상 보이되 현재 사용자가 공고를 관심 저장하기 전에는 비활성이다.
- 검색 결과는 압축된 목록 카드로 표시하고 지원 예정 배지는 상세와 같은 파란색을 사용한다. 회사명·공고 제목·출처·지원 상태·직무·지역·경력·고용 형태·마감일·기술 일치도는 실제 공고 응답에 값이 있을 때만 표시한다. 회사 로고나 대체 엠블럼은 표시하지 않는다. 목록의 관심 공고 버튼은 테두리 없이 저장 전후 픽셀 이미지만 보여 주고, 기존 북마크 API와 `bookmarked` 상태를 사용한다. 성공 문구는 카드에 표시하지 않으며 실패 오류는 표시한다. 결과 건수와 페이지는 조회 응답에서 가져온다. 검색 결과가 없으면 검색 문서와 고양이 그림, 검색어에 맞는 안내와 조건 변경 문구를 배지·테두리 없는 빈 상태로 표시한다.
- S02-V `Badge`, `LoadingState`, `ErrorState`와 색상 토큰을 재사용한다. 목록의 빈 검색은 전용 이미지 상태로, 상세의 빈 상태는 `EmptyState`로 처리한다. 목록/상세 로딩, API 실패·재시도, 범위 밖 페이지, 없는 공고를 처리한다. 북마크는 아래 S10 구현을 따르고 S11에서 내 지원 상태·필터, S12에서 AI 분석, S13에서 기술·일치도를 연결했다.
- 공고 CSS는 `frontend/src/pages/jobs/jobs.css`로 분리한다. 폼·조건은 Desktop 2열, 600px 이하 1열이며 링크·버튼·입력의 기존 포커스·44px 기준을 사용한다. 공통 `styles.css`, 상태 컴포넌트와 인증/API 클라이언트는 변경하지 않는다.
- 공유 통합 지점은 `App.tsx`의 `/jobs` 및 `/jobs/` 분기·제목, `Layout.tsx`의 채용공고 메뉴다. S04·S05의 경로·메뉴 추가를 함께 보존한다. S11은 `/applications`·상세 분기/메뉴와 `JobSummary`·`JobDetail`의 지원 상태를 연결했다. S10·S12~S13은 나머지 예약 필드와 공고 카드·상세 내부 영역을 연결한다.

## S10 구현 화면

- 공고 카드와 상세에 `관심 공고 저장` / `저장 해제` 버튼을 표시한다. 실제 `bookmarked` 값을 `aria-pressed`·아이콘·문구로 구분하며 처리 중에는 버튼을 비활성화한다. 성공 시 상태를 갱신하고 실패 시 기존 상태와 오류 안내를 유지한다. 다시 클릭해 재시도할 수 있다.
- 다른 탭에서 먼저 저장/해제해 `409`/`404`가 발생하면 상세 API로 실제 저장 상태를 다시 확인한다. 단순 중복 클릭은 차단하며 mutation을 자동 재시도하지 않는다.
- `#/bookmarks`와 `관심 공고` 메뉴를 제공한다. 기존 북마크와 직접 등록한 개인 관심공고를 최신 저장순으로 함께 표시한다. 목록의 직접 등록 버튼은 별도 `#/bookmarks/new` 페이지로, 개인 공고 수정 링크는 `#/bookmarks/{id}/edit` 페이지로 이동한다. 두 페이지는 제목·회사명·공고 링크 필수 입력과 선택 직무·경력·지역·고용형태·마감일·공고 본문·메모를 기본 정보·본문·메모 섹션으로 표시한다. 링크 확인은 URL 형식을 화면에서 검사하며 등록·수정은 기존 개인 관심공고 API를 사용한다. 목록에는 삭제·원문 링크·지원 등록을 둔다. 직접 등록 공고의 삭제는 픽셀 휴지통을 눌러 삭제 예정으로 표시한 뒤 취소하거나 별도 삭제 확정 버튼으로 실행한다. 목록 카드에서 지원 기록이 없는 수집·직접 등록 공고는 작은 지원 등록 버튼만 표시하고, 누르면 채용공고 상세와 같은 입력 폼을 펼친다. 등록 후에는 상태 배지와 지원 관리 링크를 표시한다. `#/bookmarks/{id}` 직접 등록 상세는 채용공고 상세처럼 배너·공고 요약·상세 내용/지원 현황 탭·기업 정보/AI 분석 카드를 표시한다. 본문이 있는 개인 공고에는 AI 공고분석 버튼을, 분석된 수집·개인 공고에는 필수·우대 기술을 표시한다. 수집 공고도 이 화면에서 AI 분석을 요청할 수 있다. 분석 완료 줄을 누르면 모달에서 필수·우대 기술 전체를 확인할 수 있고, 별도 결과 보기 버튼은 두지 않는다. 채용공고 목록에는 직접 등록 버튼을 두지 않는다. 로딩·빈 목록·조회/저장 오류·페이지 이동을 구분한다. 관심 목록은 공고 상세와 같은 보라·남색 카드 스타일의 압축 카드, 전체·수집·직접 등록 탭, 현재 페이지 회사명·제목·직무 검색 및 저장 시각 정렬을 제공한다. 탭별 건수는 전체가 한 페이지에 담길 때만 표시한다. 검색 결과나 저장 목록이 비면 픽셀 고양이 그림·상황별 안내·직접 등록 버튼을 표시한다. 마감일은 현재 날짜를 기준으로 D-일수·D-Day·마감으로 표시하고 원래 날짜는 툴팁에 둔다. 관심 해제 버튼은 먼저 해제 예정 안내와 취소·확정 버튼을 표시한다. 확정 시 서버에서 제거하고 화면의 카드는 빈 북마크로 남겨 재등록할 수 있게 한다. 재등록 전 새로고침하면 제거된 공고는 목록에서 사라진다. 카드의 북마크와 마감일은 같은 오른쪽 열에서 크기와 중앙 정렬을 맞춘다. 카드 아래 별도 바로가기 링크는 두지 않는다. AI 카드에는 실제 분석 상태와 추출 기술만 표시하고 서버가 제공하지 않는 일치도 점수는 만들지 않는다.
- 관심 목록에서 상세로 이동하면 `origin=bookmarks`·`from`으로 페이지를 보존하고 `← 관심 공고 목록` 링크로 복귀한다. 기존 공고 검색 목록 복귀도 유지한다. 로그인하지 않으면 기존 인증 화면으로 이동한다.
- 기존 공고 CSS·색상·픽셀 아이콘을 재사용한다. Desktop·768·390·320px 배치와 표시된 버튼의 44px 기준, 저장 해제 hover의 대비를 확인한다. 검증 결과는 [S10 기록](s10-validation.md)을 따른다.

\### Sidebar



주요 메뉴를 제공한다.

데스크톱 사이드바는 상단 메뉴 헤더의 화살표 아이콘 버튼으로 접고 펼칠 수 있다. 접은 상태에서는 메뉴 아이콘과 캐릭터만 표시하고 메뉴 링크의 접근 가능한 이름은 유지한다. 좁은 화면에서는 같은 헤더의 화살표 아이콘으로 메뉴를 열고 닫는다. 화살표 버튼은 사이드바 배경에 통합하고 버튼에 시각적 텍스트나 흰 테두리를 넣지 않는다.

사이드바는 딥 네이비 배경과 라벤더 선택 강조를 사용한다. Tailwind 유틸리티로 메뉴 헤더 높이·링크 간격·전환 및 키보드 포커스 상태를 다듬고, 좁은 화면에서는 접힌 메뉴 헤더의 불필요한 아래 여백을 줄인다. 화살표 버튼은 44px 조작 영역을 유지한다. 메뉴 항목에는 기존 Lucide 오픈소스 경로를 재사용한 서로 다른 아이콘을 배치한다. 일반 아이콘은 밝은 파랑, 활성 아이콘은 라벤더로 표시하고, 선택·누름 효과는 작은 모서리의 사각형으로 표시한다.



```text

┌────────────────┐

│ DEVJOB         │

│                │

│ 🏠 대시보드     │

│ 💼 채용공고     │

│ 📋 지원 관리    │

│ 🏢 기업 관리    │

│ 📄 이력서       │

│ 📅 면접 일정    │

│ 📚 학습 관리    │

│ 🤖 AI 분석      │

│ 🎮 내 캐릭터    │

│ ⚙ 설정          │

│                │

│ ─────────────  │

│ \[Character]    │

│ Lv.4           │

│ EXP 320/500    │

└────────────────┘

```



메뉴는 \*\*Lucide 아이콘 + 텍스트\*\* 형태를 기본으로 한다.



현재 활성화된 메뉴는 다음 방법 중 1개 또는 조합으로 구분한다.



\* 배경 강조

\* 아이콘 강조

## 6.6 S02-V 공통 UI 구현 기준 (2026-10-06)

현재 기본 화면·공통 상태·로그인·회원가입에 적용한 기준이다. 후속 기능 화면도 `frontend/src/styles.css`의 색상 토큰과 공통 컴포넌트를 재사용한다.

| 용도 | 토큰 · 색상 | 사용 기준 |
| --- | --- | --- |
| 배경 / 카드 | `--background` #f8f6f0 / `--surface` #fff | 크림 배경과 흰 카드, 얕은 테두리와 14px 모서리 |
| 본문 / 설명 | `--text` #29253e / `--muted` #615a70 | 시스템 웹 폰트, 본문 16px, 긴 이메일·오류 문구 줄바꿈 |
| 주요 행동 / 선택 | `--primary` #604583 / `--accent` #eee7f8 | 라벤더 계열 한 가지를 메인 색상으로 사용 |
| 성공 | `--success` #226249 / `--success-soft` #e6f4ed | 민트 배경, 체크 아이콘과 완료 문구 |
| 오류 | `--error` #973c49 / `--error-soft` #fff0f1 | 절제된 핑크 배경, 오류 아이콘과 원인·재시도 안내 |
| 입력 경계 | `--input-border` #93879f | 입력·일반 버튼의 경계를 배경과 구별 |

- `PixelIcon`: 로컬 SVG의 정수 좌표로 만든 픽셀 아이콘. 브랜드·메뉴·상태·배지에 사용한다. 아이콘 자체는 장식이며 항상 보이는 텍스트를 함께 제공한다.
- `PixelCharacter`: 독자적인 정적 치비 캐릭터. 기본 화면, Header의 작은 미리보기, 인증 카드, 빈 상태·성공 상태에서 사용한다. 성공 안내에는 웃는 표정을 사용한다. 성장·레벨·EXP·꾸미기·캐릭터 관리 화면은 추가하지 않는다.
- 화면 머리말의 보조 픽셀 아트는 로컬 투명 PNG를 사용한다. 인증, 대시보드, 공고·관심 공고, 지원, 프로필, 프로젝트, 역량·시장 분석 화면의 파일별 사용 경로·표시 크기·접근성·교체 기준은 [Frontend 에셋 지도](frontend-asset-map.md)에 기록한다. 의미 있는 정보나 상태는 이미지에 의존하지 않는다.
- 캐릭터는 24px 그리드 SVG를 24/48/72px로 표시하고 `crispEdges`로 렌더링한다. 색상은 `--pixel-*` 토큰을 공유하며 외부 이미지·폰트 요청이나 새 라이브러리를 사용하지 않는다. 계단형 장식은 캐릭터 받침에만 제한한다.
- `Badge`: `neutral`, `primary`, `success`, `error` 톤과 픽셀 아이콘·텍스트를 함께 제공한다. 상태를 색상만으로 구분하지 않는다.
- `LoadingState` / `EmptyState` / `ErrorState` / `SuccessState`: 로딩은 시계 아이콘·로딩 문구, 빈 상태는 캐릭터·빈 상태 문구, 오류는 오류 아이콘·안내·선택적 재시도, 성공은 캐릭터·체크 배지·완료 문구를 제공한다. 일반 안내는 `role="status"`, 오류는 `role="alert"`를 유지한다.
- `SuccessState`의 `compact` 표시를 가입 완료 후 로그인 안내에 재사용한다. 인증 오류도 픽셀 아이콘과 문구를 함께 표시한다. 입력 검증·요청 중 비활성화·인증 이동·API 계약은 S03 기준을 유지한다.
- `#/states`에서 로딩·빈 화면·오류·성공을 선택할 수 있다. 실제 처리 결과가 아닌 미리보기임을 안내하며 오류의 다시 시도는 로딩으로 전환한다.
- 버튼·입력·메뉴 링크는 최소 44px 높이, 키보드 포커스는 3px outline을 사용한다. 로딩의 약한 밝기 변화는 `prefers-reduced-motion: reduce`에서 중단하며 문구와 아이콘은 남긴다.

| 화면 폭 | 배치 |
| --- | --- |
| Desktop · 1024px 이상 | Header + 224px Sidebar + Main, 콘텐츠 최대 960px |
| Tablet · 600~1023px | 상단 접이식 메뉴, 열림 상태를 `aria-expanded`로 전달, 메뉴 선택 시 접힘 |
| Mobile · 599px 이하 | 접이식 메뉴를 세로 배치, 계정 영역 줄바꿈, 상태 선택 버튼 2열, 기본 화면 캐릭터 48px로 축소 |

검증: 프로덕션 빌드를 Edge Chromium에서 Desktop 1440×1000, Tablet 768×1024, Mobile 390×844와 320×812로 확인했다. 기본 화면, 네 가지 공통 상태, 알 수 없는 경로, 로그인·회원가입의 기본/오류/처리 중/가입 완료 표시에서 가로 넘침과 44px 미만의 버튼·입력·메뉴 링크가 없었다. 긴 이메일 줄바꿈, 메뉴 열기·닫기·선택, 오류 재시도, 키보드 본문 이동·포커스, 모션 감소도 확인했다. 토큰의 본문·설명·주요 행동·상태 색상 조합은 대비 6.06:1 이상, 입력 경계/흰 배경은 3.38:1로 계산됐다. 인증 API는 모의 응답을 사용했고 실제 Backend 연동·모바일 기기 검증은 재실행하지 않았다. Frontend `pnpm build`, 기존 API·인증 `pnpm test` 19개를 통과했다.

\## 목적

S03 구현: `#/login`은 이메일·비밀번호·로그인 버튼·회원가입 링크를 제공한다. `#/register`는 이메일·비밀번호·비밀번호 확인·가입 버튼·로그인 링크를 제공하며 확인 값은 API로 전송하지 않는다. 비밀번호는 8자 이상·UTF-8 최대 72바이트로 검증한다. 인증 화면에는 Sidebar가 없다.

\# 11. UI-004 Job Detail

S12 구현: 상세의 AI 공고 분석 영역에서 현재 계정의 첫 요청 전에는 안내와 `AI 분석하기`, `PENDING`에는 진행 상태, `FAILED`에는 일반 오류와 `다시 분석하기`, `COMPLETED`에는 정규화된 필수·우대 기술만 표시한다. 다른 계정이 분석을 완료했어도 현재 계정이 처음 버튼을 누르기 전에는 분석 전 화면을 유지한다. 첫 요청에서 공용 완료 결과가 있으면 외부 AI 호출 없이 저장된 결과를 재사용해 해당 계정의 AI 후보에 반영한다. 분석 상태는 읽기 전용 `GET /api/jobs/{jobId}/analysis`로 확인한다. 분석 영역 오류가 공고 원문·북마크·지원 UI를 가리지 않는다.

S13 구현: 목록에는 계산 가능한 기술 일치도를 표시하고, 표준 기술 검색·선택, 최소 일치도(0~100), 일치도 높은순 정렬을 제공한다. 상세에서는 분석 완료 뒤 필수·우대 기술별 일치·부족 목록과 일치도를 보여준다. 기술이나 공고 분석 기술이 없을 때는 데이터 부족 안내를 표시하며, 일치도는 합격 확률이 아님을 명시한다. 비교 조회 오류는 별도로 재시도할 수 있고 공고 원문·지원 UI는 유지한다.

공고 상세에서 `기술 비교하기`를 한 번 누른 계정은 같은 브라우저에서 해당 공고를 다시 열거나 새로고침할 때 비교 결과 영역을 바로 표시한다. 이 화면 표시 여부는 계정·공고별 브라우저 저장값으로 구분하고, 결과 자체는 저장하지 않고 매번 계정의 현재 보유·프로젝트 기술로 다시 조회한다. 다른 탭에서 기술을 바꾸고 돌아오면 재조회한다. 비교 결과의 필수·우대 기술 제목은 보조 정보 크기로 표시하고 매칭 영역 아래 구분선은 두지 않는다.

\# 12. UI-005 Application Management

지원 상세 모달의 진행 상태는 채용공고 목록·상세와 같은 선 아이콘과 상태명으로 표시한다. 공고 상세 또는 외부 원문 링크는 공고 종류 표시 오른쪽의 텍스트 링크로 둔다. 최종 합격·불합격·철회 상태에서는 면접 일정 등록과 면접 일정 보기 링크를 숨긴다.

`#/applications`는 채용공고 화면과 같은 남색 텍스트·보라색 버튼과 새 투명 픽셀 클립보드 이미지를 사용한다. 머리말 클립보드는 56px로 표시하고 원본 이미지 보간을 사용한다. Kanban 열은 상태별 파랑·민트·노랑·보라·분홍·회색 배경과 테두리로 구분하며 가용 너비에 따라 6·3·2·1열로 배치한다. 별도 회사·공고 검색창과 중복된 전역 제목은 표시하지 않는다. 열은 서류 접수·서류 합격·면접·최종 합격·불합격·기타이며 `PLANNED`·`WITHDRAWN` 기록만 기타에 둔다. 기존 `INTERESTED` 기록은 보드와 건수에서 제외한다. 열 건수는 서버의 상태별 전체 건수이고, 각 상태는 처음 100건을 가져오며 남은 기록은 더 보기로 이어서 조회한다. 카드는 작은 공고 종류 배지·회사·공고·지역·실제 지원일(있는 경우)·다음 일정·메모를 표시한다. 이미 열 제목에 표시된 상태는 카드에서 반복하지 않고, 기타 열의 지원 예정·철회만 별도 색 배지와 카드 테두리로 구분한다. 모든 열 사이에 드래그해 이동할 수 있고, 기타로 이동하면 지원 예정·철회를 선택한다. 기존 지원일이 없고 서류 접수 이후 단계로 이동하면 지원일을 필수로 받는다. 지원 예정으로 이동하면 기존 지원일을 비운다. 상태 변경 확인창은 추가 모달과 같은 보라색 버튼·남색 제목·연보라 테두리로 표시한다. 카드 제목·수정을 선택하면 보드 위 `지원 상세` 모달을 열고 실제 데이터인 상태·지원일, 값이 있는 지역·일정·메모와 공고 링크를 표시한다. 모달의 상태 변경 이력은 사용자 요청에 따라 숨기고 서버 기록은 유지한다. 상세 모달 머리말에는 새 픽셀 아이콘과 정렬된 수정·삭제·닫기 조작을 두고, 편집 폼은 모달 입력·버튼 스타일에 맞춘다. 삭제는 확인 후 실행한다. 카드 메뉴는 같은 정렬의 수정·삭제 행을 제공한다. 삭제한 기록은 보드와 공고의 지원 상태에서 숨기되 기존 이력 및 연결을 보존한다.

상단 `지원 내역 추가`는 새 투명 픽셀 이미지를 넣고 채용공고 화면과 같은 보라색 선택·버튼 및 입력창 스타일을 적용한 모달을 열어 관심 공고 또는 전체 수집 공고를 검색·선택한다. 모달은 머리말과 하단 버튼을 고정하고 입력 영역을 스크롤한다. 공고 선택 목록은 선택 표시·회사명·공고명·지역을 일정한 열로 정렬하며 새 공고 등록 링크는 가운데 정렬한다. 공고 더 보기는 목록 오른쪽의 작은 테두리 없는 버튼이다. 목록에 없는 공고는 개인 공고 등록 페이지로 이동한다. 신규 상태는 지원 예정·서류 접수·서류 합격·면접·최종 합격·불합격·철회 중 선택한다. 지원일과 진행 상태는 같은 줄에서 입력칸 윗선을 맞추고, 서류 접수 이후 진행 상태에는 지원일을 필수로 입력하며 철회에는 선택적으로 입력한다. 선택적으로 다음 확인 일정과 메모를 기록한다. 기존 `INTERESTED` 상태는 호환용 데이터와 이력에서만 유지한다.

`#/applications/{applicationId}`는 보드 위 상세 모달을 열어 메모·일정 수정과 다음 상태 선택을 제공한다. 지원일이 없는 기록을 서류 접수 이후 단계로 변경할 때 날짜를 받으며, 기존 지원일은 지원 예정으로 변경할 때만 지운다. 로딩·없는 기록·조회 오류·재시도·처리 중을 구분하고 저장 후 성공 안내 박스 없이 갱신된 정보를 보여주며, 일정은 브라우저 시간대로 입력·표시하고 API에는 시간대가 포함된 값을 전송한다. 메모는 텍스트로 표시하며 textarea 라벨을 명시적으로 연결한다. 상태 변경 이력은 모달에 표시하지 않는다. 메모·일정 저장이나 상태 변경 저장에 성공하면 수정 폼을 접고 갱신된 상세보기로 전환한다.

공고 상세의 `지원 등록하기`는 지원 관리의 추가 모달과 같은 7개 진행 상태를 선택한다. 지원일·진행 상태를 나란히 배치하고 지원 예정에서는 지원일을 비활성화하며, 철회에서는 선택적으로, 실제 지원 단계에서는 필수로 받는다. 다음 확인 일정·메모와 오른쪽 정렬의 보라색 저장·취소 버튼을 제공한다. 이미 등록된 공고에는 실제 상태와 지원 관리 링크를 보여준다. 실제 외부 지원과 CRM 기록을 구분하는 안내를 제공한다. 공고 목록은 내 지원 상태 배지와 필터를 제공한다. S02-V 공통 배지·성공/빈/로딩/오류 상태를 재사용한다.

## B04 관심 기업 관리 화면 (EXT-05-01)

- 1024px 이상에서는 목록 머리말·검색·필터·태그·건수·카드의 글씨와 조작 높이를 키워 전체 화면에서도 읽기 쉽게 한다. 좁은 화면의 크기는 유지한다. 태그 관리의 `색상 선택 *` 제목 아래에는 색상 원과 구분되는 간격을 둔다.
- 개편 목록은 새 픽셀 건물 아이콘·제목·설명·등록 버튼, 전체 폭 검색창, 산업 분야·규모·지역·관심도·정렬 선택, 점선 구분선 아래 태그 필터와 테두리 없는 큰 설정 아이콘 버튼, 결과 수와 반응형 기업 카드 그리드로 구성한다. 머리말 아래에 여백을 두고 검색창·필터 높이는 주변 조작과 균형을 맞춘다. 태그 펼침과 접기는 각각 `더보기`·`접기` 글자로 표시한다. 빈 목록은 고양이와 건물 일러스트를 보여준다. 카드에는 기업명 기반 글자 로고, 웹사이트 링크, 즐겨찾기, 수정·삭제 메뉴, 선택 태그, 메모, 실제 입력된 산업·규모·지역을 보여준다. 로고 파일·근로자 수·공고 연결 정보는 기업 기록 API에 없으므로 생성하지 않는다. 색과 버튼 상태는 지원 관리 화면의 남색·보라색을 쓴다.
- 목록 카드에는 작은 각진 모서리, 이중 픽셀 그림자, 로고·태그의 밝은 하이라이트, 메모와 기업 정보 사이의 구분선을 적용한다. 장식은 카드 안에 한정하고 정보·링크·즐겨찾기·메뉴 동작은 유지한다.
- `#/companies/new`와 상세 직접 주소는 목록 위 모달로 열 수 있다. 등록·수정 모달은 사각형 선택 탭으로 기본 정보(기업명·URL·산업·규모·지역·최대 5개 태그·메모)와 추가 정보(관심도·관리 상태·즐겨찾기)를 제공한다. 기업명과 필수 표시는 한 줄에 둔다. 태그 관리 모달은 기본 8개를 포함한 최대 30개 태그를 표·색상 선택 패널로 보여주고 추가·이름/색상 수정·드래그 순서 변경·삭제를 제공한다. 태그가 0개면 표 머리글 대신 점선 빈 목록 안내를 표시하며, 색상은 원형으로 균등 배치하고 오류는 작은 인라인 안내로 표시한다. 이름 변경과 삭제는 본인 기업 카드의 태그에도 반영한다. 기존 기록의 새 선택 필드는 기본값 또는 미입력으로 표시한다.
- 즐겨찾기 별 버튼에는 상태와 관계없이 배경색을 넣지 않는다. 상세 모달에는 단순한 픽셀 건물 아이콘, 기업명 기반 로고와 태그, 일반 텍스트·아이콘 웹사이트 링크 버튼, 3열 정보 카드(좁은 화면은 2열), 픽셀 아이콘, 메모 영역을 표시한다. 작은 이미지들은 부드럽게 축소 표시하고 메모 추가 버튼의 연필 이미지는 픽셀을 선명하게 표시한다. 정보 카드 값은 항목명과 같은 왼쪽 시작점에 정렬한다. 비어 있는 메모는 아이콘 위·문구 아래로 가운데 정렬한 점선 안내로 표시한다. 태그 옆 추가 버튼은 없으며 메모 추가 버튼은 메모가 없을 때만 보인다. 작은 수정·삭제 버튼을 유지한다. 기업 기록 저장 후 별도 완료 알림은 표시하지 않는다. 상세의 삭제 버튼은 화면 가운데 별도 확인 모달을 열고 기업명과 삭제 범위를 표시한다.

- Sidebar의 기업 관리는 #/companies로 이동한다. #/companies/new에서 등록하고 #/companies/{companyId}에서 상세·수정·삭제한다.
- 목록은 내 기록의 기업명, 관리 상태, 웹사이트, 메모, 수정일과 페이지 정보를 보여주며 동명 기업을 각각 표시한다.
- 등록·수정에는 필수 기업명과 관리 상태(INTERESTED·RESEARCHING·ARCHIVED), 선택 웹사이트·메모를 제공한다. 동일 사용자에게 같은 웹사이트 URL이 중복되면 충돌 안내를 표시한다. 웹사이트가 없는 동명 기업은 별개 기록으로 등록할 수 있다.
- 로딩·빈 목록·초과 페이지·조회 오류·상세 없음·타인 소유, 저장 중·성공·입력/중복 오류, 삭제 확인·취소·실패를 구분한다. 삭제 안내에는 공용 공고와 지원 기록이 유지됨을 명시한다.

## F09 공통 탐색·진입점 (2026-10-11)

### 전체 화면 평면 스타일 (2026-10-14)

- 공개·인증 화면을 포함한 전체 페이지의 기본 배경은 흰색이다. 공통 카드·지표·목록·상세 구획은 둥근 테두리와 그림자 대신 흰 바탕과 얇은 구분선을 사용한다. 기존 화면별 카드 색과 그라데이션은 정보 영역에서 사용하지 않는다.
- 공통 평면 스타일은 기존 Tailwind 설정을 활용한 `frontend/src/flat-pages.css`의 유틸리티 적용으로 관리한다. 이미지가 핵심인 장식 배너는 이미지를 유지하되 카드형 외곽선과 그림자를 없앤다. 입력·상태 표시·모달·차트의 의미 있는 강조는 유지한다.
- 채용공고 검색 화면의 제목 풍경 배너는 상세 배너와 같은 풍경 이미지·그라데이션·배경색과 고양이 이미지를 사용하되 `MY CAREER SPACE` 보조 문구와 카드 테두리·둥근 모서리를 없앤다. 제목은 왼쪽 정렬을 유지하고 배너 높이를 기준으로 세로 가운데에 둔다. 키워드 검색은 입력창과 버튼만 보이는 행으로, 상세 필터는 아래쪽 구분선만 있는 평면 행으로 표시한다. 검색창 아래 구분선, 검색 결과 건수의 카드 배경·테두리, 페이지 이동 영역의 위아래 구분선은 표시하지 않는다. 검색 결과 앞의 별도 탐색 머리말은 두지 않는다.
- 채용공고 출처는 배경·테두리 없는 텍스트와 아이콘으로 표시한다. 공공기관 채용에는 건물 아이콘을 사용한다. 지원 상태는 픽셀 이미지 대신 의미에 맞는 선 아이콘과 텍스트로 표시하고 출처 표시와 높이·간격을 맞춘다. 검색 결과 건수 오른쪽에는 건수와 같은 글자 크기의 테두리 없는 최신순·마감일순·기술 일치도순 정렬 선택을 두고, 페이지·공고 범위 문구는 표시하지 않는다.
- 검색 결과 건수·정렬 줄은 상세 필터와 첫 공고 사이에서 위쪽 여백, 문구의 세로 패딩, 아래쪽 여백을 작게 유지한다.
- 채용공고 상세의 저장 아이콘은 상태를 유지하며 목록보다 큰 크기로 표시한다. 상세 요약과 지원 현황의 상태도 목록과 같은 선 아이콘·텍스트를 사용한다. 게시일·마감일 위, 지원 현황의 개별 값 아래와 영역 아래, 지원 기록 등록 영역 아래에는 구분선을 두지 않고 AI 분석 영역 아래에는 얇은 구분선을 둔다. 지원 현황 값에는 배경과 테두리를 두지 않는다. `지원 상세 보기`는 지원 현황 제목 오른쪽의 텍스트 조작으로 두고, 누르면 주소 이동 없이 현재 공고 위에 기존 지원 상세 모달만 연다. 완료된 AI 분석 상태는 AI 분석 제목 오른쪽에 아이콘과 텍스트만 표시한다. 다른 계정만 AI 분석한 공고는 현재 계정에서 분석 전 화면을 보이고, 현재 계정이 분석하기를 누른 뒤 완료 결과만 표시한다.
- 관심 공고 목록 머리말은 카드 테두리·둥근 모서리·그림자 없이 연한 라벤더 배경(`#F8F5FF`)만 적용한다. 머리말과 각 공고의 AI 분석 행 아래에는 구분선을 두지 않는다. AI 분석 행에는 연한 배경만 적용한다. 현재 페이지 검색 입력창과 정렬 선택의 양 끝은 위쪽 분류 탭의 가용 영역에 맞추고, 검색 아이콘은 입력창 안에 배치한다.
- 관심 공고 목록의 지원 상태는 채용공고 목록과 같은 선 아이콘·텍스트로 표시한다. AI 분석 행은 공고 제목의 텍스트 시작점에 맞춰 작은 로봇 그림과 결과를 배치하고 별도 카드 배경을 두지 않는다. 분석 완료는 배경 배지 대신 초록 체크 아이콘과 글자로 표시한다.
- 관심 공고 AI 분석의 로봇은 기존 이미지를 유지하고 투명 여백을 고려해 영역 중앙에 배치한다. 그림 전체가 잘리지 않으면서 작은 크기에서도 선명하게 표시한다. 완료된 분석 행의 `AI 분석`을 누르면 결과 모달을 열고 별도의 `상세 보기` 문구는 표시하지 않는다. 공고 종류인 `저장한 공고`·`직접 등록`은 회사명 옆의 배경 없는 보조 텍스트로 표시한다. 목록의 `공고 수정` 링크는 숨기고 상세 화면에서 수정한다. 지원 등록 버튼 바로 아래에는 선을 두지 않고 공고 사이에는 위쪽 구분선을 둔다. 페이지 이동 영역은 위쪽 구분선만 표시한다.

- 인증된 메뉴는 대시보드, 공고·관심 공고·의미 기반 추천, 지원·면접·할 일·기업·프로필·프로젝트·이력서·자기소개서, 시장 분석·역량 분석 기반 학습·캐릭터·알림·설정을 노출한다. 상세 경로에서도 부모 메뉴가 활성화된다. 관리자 배치는 일반 메뉴에 노출하지 않는다.

### 학습 목표 통합 화면

- 상단에는 하늘·픽셀 풍경 이미지를 원본 비율대로 전부 표시하고, 별도 이동 버튼을 두지 않는다. 화면 배경은 흰색이며 분석·목표 영역과 내부 정보는 카드 테두리·그림자 대신 얇은 구분선으로 나눈다. 역량 분석 요약과 학습 목표는 1·2단계로 배치한다. 별도 Skill Gap 프론트 화면과 메뉴는 제거하고 대시보드의 분석 링크를 이 화면에 연결한다. 기존 Skill Gap API와 백엔드 비교 로직은 유지한다.
- 역량 분석 요약은 실제 `GET /api/me/skill-gap`의 분석 공고 수·부족 기술·공고 등장률과 보유 기술 숙련도만 표시한다. 계산 근거가 없는 종합 역량 점수는 표시하지 않는다. 분석 로딩·빈 상태·오류와 보유 기술 조회 오류를 독립적으로 표시한다.
- 부족 기술에서 목표 초안을 누르면 해당 기술과 제목을 입력란에 채운다. 자동 저장하지 않는다.
- 학습 목표 목록은 구분선 기반 항목, 진행률, 완료 상태, 필터와 페이지 이동을 제공한다. 상세에서는 같은 학습 목표 화면에서 체크목록을 관리한다. 항목 완료에 따른 진행률을 표시하고 진행률 100%에서 목표 완료를 허용한다. 체크목록이 있는 목표는 모든 항목 완료가 필요하며, 기존 수동 진행률 목표는 첫 체크 항목 추가 시 자동 진행률로 전환한다.
- 고정 기술 66개는 이름을 키로 한 공통 픽셀 SVG 이미지를 프로필·학습 목표·역량 분석에 동일하게 사용한다. 직접 등록 기술과 AI 발견 후보는 이름에서 안전한 2글자 표식을 즉시 만들어 같은 이미지 컴포넌트로 표시한다. 이름이 같으면 후보에서 보유 기술로 옮겨도 이미지가 같다. 기술 API에 이미지 정보가 없어 이미지는 프론트에서 생성한다.
- `#/bookmarks/{id}`, `#/interviews/{id}`, `#/learning-goals/{id}`, `#/resumes/{id}`, `#/cover-letters/{id}`, `#/recommendations/{id}`는 직접 진입 가능한 보호 경로다. `#/interviews/new?applicationId={id}`는 지원 상세에서 입력값을 전달한다.
- 설정 화면은 앱 내 알림 목록 링크를 제공한다. 관심 공고·문서 화면의 의미 기반 추천 링크는 유지하고 공고 검색 화면의 링크는 후속 UI 정리에서 제거했다. 추천 화면에서 후보와 문서 버전을 사용자가 다시 선택하며 기존 공고의 기술 일치도와 별도로 표시한다.
- 화면의 장식 이미지와 표시 크기·접근성 처리는 [개편 이미지 목록](redesign-image-manifest.md#f09-실제-화면-사용-대조-2026-10-11)에 기록한다. 실제 브라우저별 잘림과 이미지 실패 대체는 F09에서 확인되지 않았다.


## 프로필 기술 화면 (V37)

기본 정보는 닉네임/이메일, 희망 직무/경력 수준, 취업 희망 지역/학력의 균일한 2열 배치이며 좁은 화면은 1열이다. 자격증 태그 영역 아래에 저장 버튼과의 여백을 둔다. 제목 왼쪽에는 사용자가 제공한 고양이 픽셀 이미지에 맞춰 새로 만든 작은 아이콘을 표시한다. 프로필 요약 아바타는 내 캐릭터의 현재 장착 상태를 따른다. 보유 기술의 숙련도는 라벨과 값을 명시한다.

로그인 ID인 이메일은 프로필 편집에서 읽기 전용으로 표시한다. 프로필 제목 영역의 배경색은 없애고, 요약 카드에는 사용자가 제공한 풍경 참고 이미지에 맞춘 픽셀 배경을 사용한다. 장착 캐릭터는 아바타 틀 안에서 상반신 위주로 확대하며, 취업 희망 직무는 작은 회색 라벨과 다음 줄의 값으로 분리한다.
프로필 요약은 프로필 콘텐츠 영역 전체 폭의 직사각형 배너로 표시하고, 내부의 아바타와 정보는 왼쪽에 배치한다. 새 픽셀아트 풍경 배경은 가로세로 비율을 유지하며 배너 크기에 맞춰 잘라내고 아래쪽에 맞춘다. 요약 글자 뒤에는 반투명 흰색 바탕을 두어 읽기 쉽게 한다. 기본 배경은 사용자가 선택한 민트색 꽃밭 시안이며, 캐릭터 화면에서 테마를 저장하면 같은 계정의 프로필 배너에도 적용한다.

### 선택 화면 경계·동작 후속 수정

- 직접 등록 공고 폼은 첫 `기본 정보` 제목을 생략하고, 마지막 메모 아래 구분선을 없앤다. 입력 영역과 내부 구획에는 별도 배경색을 두지 않고 전체 영역을 얇은 사각형 테두리로 구분하며, 등록·수정 제출 버튼은 각각 `등록`·`저장`으로 표시한다. 직접 등록 공고 상세는 완료된 AI 분석의 필수·우대 기술을 계정의 보유 기술·직접 등록 기술 이름과 비교해 일치/미등록 목록을 요청 시 표시한다. 한 번 비교한 계정은 같은 브라우저에서 해당 공고를 다시 열거나 새로고침해도 결과 영역을 바로 표시한다. 표시 여부만 계정·공고별로 브라우저에 저장하고 비교 데이터는 현재 보유 기술 API에서 다시 읽는다. 이 비교는 이름 일치 기준이며 별도 AI 호출을 하지 않는다.
- 지원 관리 머리말은 배경색·카드 테두리·둥근 모서리·그림자 없이 아래쪽에 연한 점선 구분선만 적용한다. 칸반 전체 영역·카드의 하단 선은 없앤다. 칸반 열은 상태별 연한 배경으로 구분하고, 카드 내부의 지원일 앞에는 얇은 구분선을 둔다. 공고 제목을 누르면 목록을 다시 탐색하지 않고 현재 화면 위에 상세 모달을 연다. 지원 추가의 `지원일` 라벨은 일반 글자색을 사용하고 필수 표시만 위험 색으로 유지한다. 철회 상태는 다른 상태와 구별되는 회전 화살표 아이콘을 사용한다.
- 면접 목록의 요약 배너·수치 묶음과 보기 전환, 일정 등록 배너·추가 정보·저장 조작에는 불필요한 하단 선을 두지 않는다. 개별 요약 수치와 달력·선택 날짜 영역은 얇은 사각형 테두리로 구분한다. 선택 날짜 안의 일정은 테두리 없이 연한 배경색으로만 구분한다. 달력의 일요일은 빨강, 토요일은 파랑으로 표시한다. 면접 상세의 취소 조작은 다른 상태 조작과 간격을 두어 구별한다.
- 할 일 머리말은 배경색·카드 테두리·둥근 모서리·그림자 없이 아래쪽에 연한 점선 구분선만 적용한다. 달력·선택 날짜·전체 목록은 사각형 테두리로 구분한다. 프로필 보유 기술 항목·기술 검색·AI 발견 후보도 얇은 테두리로 구분한다. 채용시장 분석의 네 가지 바로가기 탭을 없애고 네 분석 구획을 한 화면에 유지한다. 분석 전체 영역은 사각형 테두리로 표시하고, 관심 기업 카드는 얇은 테두리와 자연스러운 둥근 모서리로 구분한다. 대시보드의 `MY CAREER SPACE` 보조 문구와 가입 뒤 로그인 화면의 별도 완료 알림은 표시하지 않는다.
- 프로필의 기본 정보·보유 기술·기술 검색·AI 발견 후보 머리말에는 하단 선을 표시하지 않는다. 기술 검색 결과와 AI 발견 후보의 각 항목은 점선으로 구분한다. 채용시장 분석 머리말 아래 여백을 늘리고 조건 설정 제목과 적용 버튼은 오른쪽에 배치하며 조건 설정 아래 구분선은 없앤다. 분석 요약 수치 네 개는 테두리 없이 연한 배경색으로 구분하고 분석 전체 영역에는 얇고 둥근 테두리를 적용한다. 역량 분석 화면의 배너 이미지와 영문 보조 문구는 제거한다. 학습 기술의 숙련도도 `입문`·`초급`·`중급`·`숙련`·`고급`으로 표시한다. 내 할 일 머리말 제목은 다른 페이지의 제목 크기에 맞춘다. 공통 헤더의 계정명과 로그아웃 사이에 알림 화면 링크 버튼을 둔다.
- 공통 헤더의 알림은 둥근 종 모양 아이콘으로 표시하고 로그아웃은 밑줄·테두리·배경이 없는 텍스트 버튼으로 표시한다. 내 캐릭터 화면은 꾸미기 안내, 프로필 테마, 캐릭터 미리보기와 의상·헤어·안경 탭, 테마 즉시 적용, 퀘스트·EXP 활동·보상 수령 내역 탭 순서로 배치한다. 테마는 기존 프로필 픽셀 배경 3개와 새 달빛 마을·가을 숲·눈 내린 마을·바닷가 배경 4개를 사용한다. 배경의 가로세로 비율을 유지하며 카드 크기에 맞춰 자르고, 선택한 테마는 계정 ID별로 현재 브라우저에 저장한다. 의상·헤어·안경 장착은 기존처럼 선택 즉시 서버에 저장한다. 퀘스트 목록은 실제 서버 실적과 보상 의상 이름·진행도·관련 화면 링크를 보여 주며, 이미 받은 의상은 보상 내역에도 표시한다.
- 내 캐릭터 화면의 넓은 배치에서는 왼쪽에 캐릭터 미리보기·레벨을 놓고, 오른쪽에 테마 7개를 한 줄로 선택하는 영역과 꾸미기 탭·아이템을 쌓는다. 좁은 화면에서는 영역들을 세로로 배치한다. 머리말 아이콘은 색 수를 줄인 투명 배경의 회보라색 고양이 얼굴 픽셀 그림을 축소 시 가장자리 계단 현상이 두드러지지 않게 표시하고, 전체 모습이 잘리지 않으며 글자 영역을 침범하지 않게 배치한다. 머리말 아래에는 연한 점선 구분선을 두고 프로필 테마 아래 구분선과 미리보기의 외곽 테두리는 없앤다. 꾸미기 영역은 얇고 둥근 테두리로 감싸고 제목 주변 여백을 줄이며, 아이템 목록 아래 구분선은 표시하지 않는다. 테마 선택은 클릭 즉시 현재 브라우저의 계정별 설정에 저장·적용하며 별도의 기본 테마·저장 버튼을 표시하지 않는다. 미리보기 배경이 더 보이도록 아바타를 조금 줄이고 부드럽게 표시하며 `현재 선택한 모습` 문구는 없앤다. 레벨은 누적 EXP·진행 막대·현재/목표 EXP를 분리해 보여 준다. 꾸미기는 아이콘 탭과 선택·잠김 상태가 구분되는 연한 색상 카드로 표시하고, 아이템 이미지는 조금 크게 하되 축소 시 부드럽게 렌더링한다. 의상 탭 머리말은 `의상 선택`과 퀘스트 달성으로 얻는 의상 안내를 표시한다. 잠긴 보상에는 자물쇠 선 아이콘을 사용한다. 보상 수령 직후의 큰 축하 알림은 표시하지 않는다. 상태 다시 조회 버튼은 `최신 정보 불러오기`로 표시한다.
- 활동과 보상 영역은 절제된 색상의 픽셀 배너와 세 가지 탭으로 구성한다. 배너에는 여백이 적고 선명한 트로피 그림을 크게 배치하고, 제목과 설명은 배너에 어울리는 크기로 표시하되 배경 그림을 가리지 않게 한다. 보상 수령 내역 탭에는 선명한 선물 픽셀 아이콘을 사용하고 보상 요약 카드에는 같은 그림을 더 크게 표시한다. 안내 문구에서 개인 할 일 EXP 지급 설명은 제거한다. 퀘스트에는 할 일·공고 저장·이력서·지원 기록·학습·AI 분석별 새 픽셀 아이콘, 실제 진행도, 보상 의상 이미지와 수령 또는 이동 조작을 가로형 카드로 표시한다. 활동 내역에는 서버가 반환한 EXP 기록만 아이콘·획득량·시간과 함께 표시한다. 보상 수령 내역에는 실제 보유 의상 수와 누적 EXP, 수령한 퀘스트 보상 및 진행 중인 보상을 표시하며, 수령한 보상이 없으면 고양이 픽셀 그림과 안내를 표시한다. 좁은 화면에서는 카드 내용을 세로로 재배치한다.

기술 검색에는 고정 시스템 목록만 보인다. 추가 버튼을 누르면 숙련도를 선택하고 등록할 수 있다. 목록에 없는 이름은 계정별 직접 등록 기술로 추가되며, 시스템 기술과 같은 카드 UI에서 이름·숙련도를 수정하고 삭제한다. AI 공고 분석 결과는 `AI` 표시가 있는 별도 후보 목록으로 보여 주고, 사용자가 보유 기술로 명시적으로 추가하거나 후보를 삭제할 수 있다. 후보는 자동으로 보유 기술에 들어가지 않는다. 빈 후보 상태에는 이미지와 분석 방법 안내를 보여 준다. 중복 등록의 화면 오류 문구는 `이미 등록된 기술입니다.`로 표시한다.
보유 기술 카드는 가용 폭에 맞춰 열 수를 줄여 이름과 메뉴가 잘리지 않게 하고, AI 후보는 짧은 카드로 여러 열에 배치한다. 후보 카드에는 `AI` 배지, 기술 이미지, 기술명, 추가·삭제 버튼을 순서대로 표시하며 배지의 너비를 고정해 기술명이 늘어날 수 있게 한다. 검색 결과와 AI 후보의 추가 버튼은 `+`, 후보 삭제는 휴지통, 새로고침은 회전 화살표 아이콘으로 표시하며 접근성 이름을 제공한다.
추가 시 숙련도 선택은 검색 결과 밑의 인라인 폼 대신 모달로 보여 준다. 비어 있는 보유 기술 카드에서는 이미지와 안내 문구를 카드 높이의 가운데에 둔다. 기술 검색의 도움말은 시스템 목록과 계정별 직접 등록만 설명하며, AI 후보 설명은 후보 영역에서 제공한다.
관심 공고의 완료된 분석 카드에도 `AI 분석하기` 버튼을 유지한다. 버튼은 기존 POST를 호출하고, 공용 완료 결과가 있으면 그 결과를 재사용해 계정별 AI 후보에 반영한다. 카드의 결과 조회와 프로필 후보 새로고침은 후보를 추가하지 않는다.
다른 계정만 분석을 완료한 수집 공고는 현재 계정에서 미분석으로 표시하며 평소와 같은 `AI 분석하기` 버튼을 보여 준다. 이 계정이 버튼을 누른 뒤에만 완료 상태와 기술을 표시한다.
고정 목록 확정 전 등록된 비고정 보유 기술은 수정할 때 계정별 기술로 전환한다. 기존 숙련도를 편집기에 보여 주고, 이름 변경 후 다른 계정에 영향을 주지 않는다.
