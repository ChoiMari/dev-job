\# DevJob UI Specification



\## 1. 문서 목적



본 문서는 \*\*DevJob\*\*의 프론트엔드 UI(User Interface) 구현을 위한 화면 및 디자인 명세서이다.



프론트엔드 개발자는 다음 문서를 함께 참고한다.



\* `requirements.md` — 제품 및 기능 요구사항

\* `user-flow.md` — 사용자 흐름

\* `ui-spec.md` — 화면 및 UI 구현 기준

\* `api-spec.md` — 백엔드 API 계약



본 문서에서는 특히 다음을 정의한다.



\* 화면 구성

\* 화면 간 이동

\* 레이아웃

\* 컴포넌트

\* UI 상태

\* 사용자 인터랙션

\* 디자인 원칙

\* 반응형 기준

\* 픽셀 아트 캐릭터 및 게이미피케이션 적용 규칙



\---



\# 2. DevJob UI Design Direction



\## 2.1 핵심 컨셉



DevJob은 \*\*현대적인 취업지원 SaaS + 귀여운 픽셀 아트 게임 감성\*\*을 결합한다.



DevJob은 게임이 아니다.



실제 취업 준비와 지원 관리를 위한 \*\*생산성 중심 CRM\*\*을 기반으로 하며, 픽셀 아트와 가벼운 게이미피케이션을 통해 서비스의 개성을 만든다.



\### 핵심 키워드



\* Cute Pixel Art

\* Chibi

\* Retro RPG

\* Pixel UI

\* Cozy

\* Productivity

\* Career Dashboard

\* Gamification

\* Modern SaaS



\---



\# 3. UI 기본 원칙



\## 3.1 SaaS 사용성 우선



전체 서비스 구조는 일반적인 현대 SaaS 서비스처럼 구성한다.



\* 명확한 정보 계층

\* 빠른 탐색

\* 일관된 버튼 및 입력 UI

\* 데이터 중심 화면

\* 충분한 여백

\* 명확한 상태 표시

\* 모바일 및 태블릿 대응



픽셀 아트 요소 때문에 실제 업무용 서비스의 가독성과 사용성이 떨어지면 안 된다.



\---



\## 3.2 픽셀 아트는 Identity로 사용



픽셀 아트는 서비스 전체를 게임 화면처럼 만드는 용도가 아니다.



다음 요소를 중심으로 제한적으로 사용한다.



\* 캐릭터

\* 아이콘

\* 배지

\* EXP

\* Level

\* 일부 상태 표시

\* Empty State

\* Success State

\* 장식용 요소



\### 피해야 할 것



\* 화면 전체를 레트로 게임 UI처럼 구성

\* 과도한 픽셀 테두리

\* 과도한 애니메이션

\* 지나치게 많은 캐릭터

\* HUD 형태의 복잡한 화면

\* 정보보다 장식이 강조되는 UI

\* 모든 텍스트를 픽셀 폰트로 표현

\# 4. 전체 Layout



\## 4.1 Desktop



기본 레이아웃은 Sidebar + Header + Main Content 구조를 사용한다.



```text

┌─────────────────────────────────────────────────────┐

│ Header                                              │

├───────────────┬─────────────────────────────────────┤

│               │                                     │

│   Sidebar     │           Main Content              │

│               │                                     │

│               │                                     │

│               │                                     │

└───────────────┴─────────────────────────────────────┘

```



\### Sidebar



주요 메뉴를 제공한다.



```text

┌────────────────┐

│ DEVJOB         │

│                │

│ 🏠 대시보드     │

│ 💼 채용공고     │

│ 📋 지원 관리    │

│ 🏢 기업 관리    │

│ 📄 이력서       │

│ 📅 면접 일정    │

│ 📚 학습 관리    │

│ 🤖 AI 분석      │

│ 🎮 내 캐릭터    │

│ ⚙ 설정          │

│                │

│ ─────────────  │

│ \[Character]    │

│ Lv.4           │

│ EXP 320/500    │

└────────────────┘

```



메뉴는 \*\*픽셀 아이콘 + 텍스트\*\* 형태를 기본으로 한다.



현재 활성화된 메뉴는 다음 방법 중 1개 또는 조합으로 구분한다.



\* 배경 강조

\* 픽셀 형태의 Accent

\* 작은 Dot

\* 아이콘 강조



과도하게 깜빡이거나 움직이지 않는다.

\# 6. Design System



\## 6.1 Color



전체적으로 밝고 깨끗한 배경을 사용한다.



주요 색상 계열:



\* Cream

\* Warm Pink

\* Lavender

\* Mint

\* Light Sky Blue

\* Dark Navy / Purple



모든 색상을 동시에 사용하는 것은 피한다.



\### 기본 원칙



```text

Background

&#x20;   ↓

Neutral / Cream



Primary

&#x20;   ↓

Warm Pink 또는 Lavender



Secondary

&#x20;   ↓

Mint / Sky Blue



Text

&#x20;   ↓

Dark Navy / Purple

```



화면마다 Main Color 1개와 Supporting Color 2\~3개 정도를 사용하는 것을 권장한다.



\---



\# 6.2 Typography



본문 및 일반 데이터는 일반적인 웹 폰트를 사용한다.



픽셀 폰트는 제한적으로 사용한다.



\### 일반 폰트 사용



\* 본문

\* 설명

\* 채용공고

\* 회사명

\* 입력값

\* 표

\* 버튼

\* 긴 문장



\### Pixel Font 사용



\* 캐릭터 이름

\* EXP

\* Level

\* 특별한 Badge

\* 일부 게임 상태 표시

\* 장식용 타이틀



가독성이 필요한 영역에서는 픽셀 폰트를 사용하지 않는다.



\---



\# 6.3 Card



Card는 DevJob의 주요 정보 표현 단위이다.



기본 형태:



```text

┌──────────────────────────────┐

│ Title                   Badge │

│                              │

│ Description / Data           │

│                              │

│ Meta              Action     │

└──────────────────────────────┘

```



특징:



\* 약간 둥근 모서리

\* 또는 매우 약한 Pixel Corner

\* 과도한 그림자 금지

\* 과도한 Gradient 금지

\* 충분한 내부 여백

\* 명확한 정보 계층



\---



\# 6.4 Button



주요 Action은 명확하게 표현한다.



예:



\* 지원하기

\* 저장하기

\* 분석하기

\* 수정하기

\* 삭제하기

\* 상태 변경

\* 프로젝트 추가



Primary Action은 한 화면에서 지나치게 많이 사용하지 않는다.



\---



\# 6.5 Badge



Badge는 상태나 분류를 빠르게 보여주는 용도로 사용한다.



예:



```text

\[필수]

\[우대]

\[지원 예정]

\[지원 완료]

\[서류 통과]

\[면접]

\[AI 분석 완료]

```



색상만으로 상태를 구분하지 않는다.



\*\*아이콘 + 텍스트 + 색상\*\*을 함께 사용하는 것을 기본으로 한다.

\# 9. UI-002 Dashboard



\## 목적



사용자가 자신의 취업 준비 상황을 한 화면에서 확인한다.



\## 상단



```text

안녕하세요, OO님!

오늘의 취업 준비를 시작해볼까요?

```



캐릭터가 간단한 contextual message를 제공할 수 있다.



예:



> 오늘은 지원하기 좋은 공고가 3개 있어요.



캐릭터는 정보를 전달하는 보조 역할이며 핵심 데이터보다 강조하지 않는다.



\---



\## 주요 지표



```text

┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐

│ 지원 예정 │ │ 지원 완료 │ │ 면접 예정 │ │ 관심 공고 │

│    5     │ │    12    │ │    2     │ │    18    │

└──────────┘ └──────────┘ └──────────┘ └──────────┘

```



\---



\## 오늘의 할 일



Checkbox 기반으로 제공한다.



```text

오늘의 할 일



☐ A회사 공고 확인

☐ 이력서 수정

☐ Spring 학습

☑ B회사 지원 완료

```



완료 시 가벼운 EXP 피드백을 제공할 수 있다.
