# 로컬 고정 데이터 환경

로컬 앱의 지속 사용 DB는 Docker Compose 프로젝트 `devjob-live`, 컨테이너 `devjob-live-postgres-1`, DB `devjob_live`, 볼륨 `devjob-live_postgres-data`, 호스트 포트 `127.0.0.1:55450`이다. 테스트 DB와 기존 `devjob`·`devjob-s17-demo` 컨테이너는 별개다. 기존 데이터는 삭제하거나 이 DB로 복사하지 않았다.

2026-10-13 프로필 기술 화면 작업에서는 기존 8097 API를 유지한 채 이 작업 폴더의 Backend를 8098에 띄웠다. `http://127.0.0.1:5174` 개발 화면의 `/api` 프록시는 8098을 가리키며 두 API는 모두 같은 고정 DB `devjob_live:55450`을 사용한다. V37·V38에 이어 V39는 승인된 66개 외 공용 기술과 연결 별칭·공고 기술 관계를 제거한다. 분석 JSON과 계정별 기술은 유지한다. 8098 서버는 별도 메모리 세션을 사용하므로 기존 8097 로그인 세션은 공유되지 않는다.

루트의 무시된 `.env.live`는 DB 접속 정보와 공공 API 키를 보관한다. Git에 추가하지 않는다. 이 파일의 `DB_NAME=devjob_live`, `DB_HOST=127.0.0.1`, `DB_PORT=55450`을 고정하고, Backend는 `scripts/start-live.ps1`로 기동한다. 시작 스크립트는 다른 DB 대상이면 실행을 거부한다. Backend JAR을 새로 빌드한 뒤 기존 API 프로세스를 종료하고 스크립트를 다시 실행한다. 현재 5174 Frontend의 `/api` 프록시는 무시된 `frontend/.env.local`에서 8098을 사용한다.

이력서 원문·임시저장·자기소개서에는 `.env.live`의 `RESUME_ENCRYPTION_KEY`(32바이트를 Base64로 인코딩)가 필요하다. 누락되거나 형식이 틀리면 저장·원문 조회가 `503`으로 거부된다. 기존 암호문이 있다면 반드시 같은 키를 유지해야 한다. 2026-10-16에는 로컬 DB의 이력서 버전·자기소개서 버전·초안이 모두 0건인 것을 확인한 뒤 키를 한 번 생성해 무시된 `.env.live`에 저장하고 8098 API를 재시작했다. 키 값은 문서·Git·로그에 남기지 않는다.

AI 분석에는 별도의 `OPENAI_API_KEY`가 필요하다. 기본 체크아웃의 `.env`는 `scripts/start-live.ps1`이 읽지 않으므로, 실제 로컬 서버에서는 무시된 `.env.live`에 이 키를 설정하고 서버를 재시작해야 한다. 키 값은 문서나 Git에 기록하지 않는다.

`docker compose -p devjob-live --env-file .env.live stop postgres`는 데이터를 보존한다. `down -v`와 볼륨 삭제는 사용하지 않는다. 새 DB로 전환했으므로 기존 시연 DB의 계정·개인 기록은 이 환경에 없고 사용자는 새 계정을 등록해야 한다.

2026-10-16 로컬 `devjob_live`에 이력서 양식 암호문용 Flyway V47을 적용하고 8098 API를 새 JAR로 재시작했다. 기존 이력서·버전 행은 유지한다. 구조화 양식 데이터는 이 변경 이후 저장한 버전에만 존재한다.

2026-10-17에는 자기소개서 임시저장 테이블·인덱스를 추가하는 Flyway V48을 `devjob_live`에 적용했다. 같은 DB·기존 `RESUME_ENCRYPTION_KEY` 설정으로 이 작업 폴더의 새 JAR을 8098 API에 기동했고, Flyway 로그에서 스키마 버전 48과 서버 시작을 확인했다. 5175 개발 화면의 `/api/me/cover-letters/drafts` 요청은 로그인하지 않은 상태에서 401을 반환했다. 서버 재시작으로 기존 로그인 세션은 다시 로그인해야 할 수 있다.

같은 날 프로젝트 개인/팀 유형 컬럼을 추가하는 Flyway V49를 고정 DB `devjob_live:55450`에 적용했다. 이 작업 폴더의 새 JAR을 8098 API에 재시작했고, Flyway 로그에서 스키마 버전 49와 Tomcat 8098 시작을 확인했다. `GET /api/me/projects`는 비로그인 요청에 401을 반환했다. 기본 체크아웃의 `.env`는 다른 DB를 가리켜 사용하지 않았다.

2026-10-17 프로젝트 상세 입력·이미지 메타데이터용 Flyway V50·V51을 같은 고정 DB에 적용했다. 기존 행을 보존하는 추가 migration이며, 로그에서 스키마 버전 51과 8098 API 기동을 확인했다. 프로젝트 이미지 S3 버킷은 아직 없다. 생성 후 비공개 버킷의 이름·리전을 `.env.live`의 `PROJECT_IMAGE_S3_BUCKET`·`PROJECT_IMAGE_S3_REGION`에 설정하고, 8098 프로세스의 AWS 기본 자격 증명 체인에 해당 버킷의 객체 Put/Get/Head/Delete 권한을 제공해야 한다. 버킷 CORS는 `http://127.0.0.1:5175` 출처의 PUT과 `Content-Type` 헤더를 허용한다. 키·자격 증명은 Git에 넣지 않는다. 설정 전에는 이미지 API만 503이며 프로젝트 텍스트 CRUD는 계속 동작한다.

2026-10-17 담당 기능별 기여도·트러블슈팅 반복 항목용 Flyway V52도 같은 고정 DB에 적용했다. 기존 단일 값은 배열로 이관하며, 로그에서 스키마 버전 52와 8098 API 기동을 확인했다.

2026-10-17 프로젝트 직접 입력 기술 관계용 Flyway V53을 같은 고정 DB에 적용했다. 기존 프로젝트 행은 변경하지 않는다. 분리된 `devjob_s06_test`·`devjob_b15_test`에서 프로젝트 저장·검색과 계정 삭제 통합 테스트를 실행한 뒤 새 JAR로 8098 API를 재시작했다. 로그에서 스키마 버전 53과 Tomcat 8098 시작을 확인했고, 비로그인 프로젝트 목록 요청은 401을 반환했다. API 재시작으로 기존 로그인 세션은 다시 로그인해야 할 수 있다.

2026-10-11 최초 구축에서 기존 ALIO 수동 수집 API가 실제 공공 API 키로 호출됐고, `ALIO_RECRUITMENT` 공고 3건이 저장됐다. 응답은 `PARTIAL_FAILURE`(created 3, rejected 1, failed 0)였으며 성공한 공고는 유지됐다. 수집을 위해 만든 임시 계정은 삭제했다. 이후 공고 조회는 저장된 DB를 읽으며 화면 진입만으로 외부 API를 다시 호출하지 않는다.

2026-10-12에는 관리자 전체 수집 API로 진행 중인 정보통신 NCS `R600020` 공고를 마지막 페이지까지 수집했다. 결과는 `COMPLETED`, 처리 3페이지, 신규 39건, 중복 3건, 거절·실패 0건이다. DB의 ALIO 공고는 총 42건이며 수집용 임시 계정은 삭제했다. 이 배치는 일반 사용자 수동 수집 API의 3페이지·제목 IT 키워드 제한을 적용하지 않는다.
