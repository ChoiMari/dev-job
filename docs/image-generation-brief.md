# DevJob 이미지 제작 공통 가이드

상태: 제작 기준 및 후속 이미지 요청용 문서 · 2026-10-08

2026-10-10 프론트 개편 계획: [요구사항의 페이지별 이미지 기준](frontend-redesign-requirements.md#31-페이지별-이미지-작업-기준)에 따라 화면마다 기존 산출물을 먼저 검토하고 부족한 이미지는 구현 단계에서 `imagegen` 스킬의 내장 `image_gen`으로 새로 만든다. 공개 홈 전용 `CUR-15`는 **예정 항목**이며 아래 완료 수량에 포함되지 않는다. 해당 이미지가 생성·채택되면 [산출물 목록](redesign-image-manifest.md)에 실제 파일·사용처·접근성 처리를 기록한다.

현재 목록의 장식 이미지 26개와 별도 브랜드 로고 2개를 제작해 `frontend/src/assets/redesign/`에 저장했다. 실제 파일명·크기·사용처·검증 상태는 [산출물 목록](redesign-image-manifest.md)을 따른다. 이 문서의 아래 프롬프트 틀은 후속 변형 제작용이다.

> 이미지 제작을 요청할 때: **“`docs/image-generation-brief.md`를 먼저 읽고, 에셋 ID `[ID]`의 이미지를 제작해 줘. `docs/assets/frontend-redesign-reference.png`는 스타일 참고로 사용하고, 기능·문구·수치는 복사하지 마.”**

이 문서는 앞으로 생성할 이미지를 일관된 시각 언어로 맞추기 위한 **프롬프트 기준**이다. [디자인 개편안](frontend-redesign-proposal.md)은 화면 배치, [확장 요구사항](extension-requirements.md)과 [확장 UI 명세](extension-ui-spec.md)는 후속 기능의 범위를 설명한다. 이미지를 만들 때는 이 문서와 **선택한 에셋 행**을 함께 참고한다. 새 이미지는 전부 `frontend/src/assets/redesign/`에 모으며 기존 `frontend/src/assets/illustrations/`의 파일을 재사용하거나 덮어쓰지 않는다.

## 1. 가장 중요한 경계

- 첨부 [참고 이미지](assets/frontend-redesign-reference.png)는 색감·밀도·픽셀 아트 분위기·화면과 일러스트의 균형을 참고한다. 이미지에 보이는 회사명, 숫자, 체크박스, 메뉴, 레벨, EXP, 장착 아이템, 가상의 분석 결과를 실제 제품 사실로 옮기지 않는다.
- **이미지 안에 UI를 그리지 않는다.** 버튼·입력·카드·배지·차트·숫자·텍스트는 프론트 코드와 실제 데이터로 렌더링한다. 생성 이미지는 배경, 장면, 캐릭터, 작은 장식 그림에 한정한다.
- 사용자 사진, 기업 로고, 외부 채용 서비스 로고, 실제 채용공고 내용은 생성하지 않는다. 현재 회사 로고 데이터가 없으므로 공고 카드의 대체 표식은 코드에서 만든다.
- 아직 구현되지 않은 확장 기능의 이미지를 먼저 만들어도 제품 화면에 활성 기능처럼 노출하지 않는다. 아래 `확장 전용` 에셋은 해당 기능의 요구사항과 UI가 확정됐을 때 사용한다.
- 같은 에셋을 다양한 상태의 의미로 오용하지 않는다. 예를 들어 체크가 그려진 장식 그림은 실제 지원 완료를, 막대 그림은 실제 시장 수치를 뜻하지 않는다.

## 2. 공통 아트 디렉션

| 항목 | 프롬프트에 넣을 기준 |
| --- | --- |
| 스타일 | 현대적인 취업 준비 SaaS에 어울리는 **깔끔한 픽셀 아트 일러스트**. 또렷한 픽셀 가장자리, 읽기 쉬운 실루엣, 작은 크기에서도 구분되는 형태. |
| 분위기 | 차분하고 따뜻하며 조금 귀엽다. 과한 게임 화면, 공격적인 네온, 복잡한 판타지 장식은 피한다. |
| 팔레트 | 짙은 남보라·인디고를 중심으로 연보라, 크림, 연분홍, 민트, 복숭아색을 보조로 사용한다. 참고 이미지와 어울리되 최종 색은 프론트 토큰과 함께 확인한다. |
| 빛과 배경 | 부드러운 아침/노을빛, 은은한 구름·꽃잎·작은 반짝임은 넓은 배너에만 제한한다. 작은 아이콘은 단순한 단색 또는 투명 배경으로 둔다. |
| 캐릭터 | 이번 개편용 캐릭터를 처음부터 하나의 기준 시트로 정의한다. 같은 캐릭터를 반복 생성할 때 머리·얼굴·옷의 기본 형태와 팔레트를 일정하게 유지한다. |
| 정보 밀도 | 이미지 자체는 장식이다. 핵심 데이터가 들어갈 카드 영역에 강한 패턴·캐릭터를 겹치지 않는다. |
| 금지 요소 | 읽을 수 있는 글자, 숫자, 로고, 버튼, 입력창, 실제 통계 그래프, 회사 상표, 사진 같은 얼굴, 워터마크. |

프롬프트의 색상 단어만으로 최종 색을 확정하지 않는다. 생성 후 실제 화면의 흰 카드·어두운 사이드바·보라색 버튼 옆에 놓아 색과 대비를 확인한다. 장식 이미지의 `alt`는 원칙적으로 빈 문자열이며, 캐릭터 자체가 중요한 의미를 전달하는 경우에만 맥락에 맞는 대체 설명을 작성한다.

## 3. 이미지 유형과 산출 기준

| 유형 | 권장 형태 | 배경 | 사용 방식 |
| --- | --- | --- | --- |
| A. 넓은 장면 | 가로형 또는 세로형 배너, 중요한 피사체는 중앙/한쪽에 두고 텍스트를 얹을 빈 공간 확보 | 장면 배경 포함 | 로그인 분할 화면·대시보드 머리말의 장식. 텍스트는 코드에서 별도 배치 |
| B. 카드 장식 | 정사각형에 가까운 작은 사물/장면, 바깥 여백 확보 | 투명 | 공고·프로필·프로젝트 등 카드 머리말 |
| C. 캐릭터 | 동일한 실루엣·팔레트의 전신 또는 반신, 정면/측면 등 필요한 방향을 명시 | 투명 | 안내·빈 상태·성공 상태. 상태별 표정은 요청마다 명시 |
| D. 기능 전용 장면 | 해당 기능을 연상시키는 **상징적** 소품/배경 | 목적에 따라 투명 또는 장면 배경 | 확장 화면의 머리말. 실제 기록·점수·완료 상태를 표현하지 않음 |

한 장의 생성 요청은 **에셋 한 종류와 사용 위치 하나**를 기준으로 한다. 여러 화면 전체를 한 번에 생성한 콜라주는 실제 UI에 잘라 쓰지 않는다. 배경 제거가 필요한 B·C 유형은 처음부터 투명 배경을 요청한다. 픽셀 에셋은 불필요한 흐림·안티앨리어싱을 피하고, 작은 표시 크기로 축소했을 때 형태가 유지되는지 확인한다.

제작물은 우선 원본과 실제 배치용 파일을 구분해 검토한다. 채택한 이미지만 `frontend/src/assets/redesign/`에 에셋 ID와 용도가 드러나는 이름으로 저장한다(예: `cur-01-login-scene.png`). 원본 후보를 여러 개 보관한다면 같은 새 폴더 안에서 이름으로 구별한다. 기존 장식 이미지 폴더는 이번 제작의 입력이나 출력으로 사용하지 않는다. 참고 스크린샷 자체도 제품 배경으로 사용하지 않는다.

## 5. 확장 기능용 에셋 목록

이 표는 [확장 요구사항](extension-requirements.md)의 ID와 연결한다. 이미지가 먼저 만들어져도 기능 구현과 사용자 데이터가 준비되기 전에는 장식 자산으로만 보관한다.

확장 이미지도 같은 `frontend/src/assets/redesign/`에 저장한다. 파일명은 에셋 ID를 소문자로 바꾼 접두어와 용도를 조합한다(예: `ext-img-05b-resume-empty.png`).

| ID | 요구사항 | 사용 예정 영역 | 제작 후보 | 이미지가 표현하면 안 되는 것 |
| --- | --- | --- | --- | --- |
| EXT-IMG-01 | EXT-01 계정 설정 | 보안/알림 설명 머리말 | 자물쇠·봉투의 작은 **중립 소품**. 실제 설정 화면에 큰 배경은 불필요 | 보안 검증 완료, 알림 발송 성공, 계정 삭제 성공 |
| EXT-IMG-02 | EXT-02 기술 숙련도 | 보유 기술 편집 안내 | 쌓이는 블록·도구 상자 등 성장의 은유 | 특정 숙련도 점수·연차·등급 |
| EXT-IMG-03 | EXT-03 개인 할 일 | 개인 할 일의 빈 상태 | 빈 체크리스트·연필·작은 책상 | 실제 완료 체크, EXP 지급 |
| EXT-IMG-04 | EXT-04 확장 분석 | 경력/지역/기간별 통계 구역의 머리말 | 달력·지도 핀·추상 그래프의 작은 소품 | 실제 분포·비율·기간 수치 |

## 6. 제작 요청에 복사할 프롬프트 틀

아래 틀에서 대괄호를 채우고 **에셋 ID 하나만** 지정한다. 결과를 저장소에 적용해 달라는 요청은 이미지 선택과 화면 검증을 마친 뒤 별도로 한다.

```text
docs/image-generation-brief.md를 읽고 [에셋 ID] 이미지를 제작해 줘.
스타일 참고: docs/assets/frontend-redesign-reference.png.
관련 화면: [화면 경로/위치]. 목적: [장식이 돕는 맥락 한 문장].
유형: [넓은 장면 / 투명 배경 카드 장식 / 투명 배경 캐릭터 / 기능 전용 장면].
구도: [가로/세로/정사각형, 피사체 위치, 텍스트가 들어갈 빈 공간].
반드시 유지할 요소: [CUR-10 캐릭터 기준 시트와의 관계 또는 팔레트/소재].
넣지 말 요소: 읽을 수 있는 글자, 숫자, 버튼, 입력창, 가짜 데이터, 회사 로고, 워터마크.
이번 요청에서는 [시안 수]개의 시안을 보여줘. 채택하면 frontend/src/assets/redesign/의 제안 파일명으로 저장하고, 기존 장식 이미지 폴더의 파일은 건드리지 마.
```

### 예시: 로그인 장면 요청

```text
docs/image-generation-brief.md의 CUR-01을 기준으로 로그인 화면용 세로형 픽셀 아트 장면을 제작해 줘.
docs/assets/frontend-redesign-reference.png의 남보라·연보라·복숭아색 도시 노을 분위기만 참고해.
작은 캐릭터가 취업 준비의 새 출발을 바라보는 장면으로, 입력 폼은 별도 HTML 영역에 들어가므로
그림에는 로고·글자·폼·버튼·숫자를 넣지 마. 좁은 모바일 화면에서 잘려도 주 피사체가 남도록 구성해.
시안을 먼저 보여주고, 채택한 결과만 frontend/src/assets/redesign/cur-01-login-scene.png로 저장해 줘.
```

### 예시: 확장 기능 장식 요청

```text
docs/image-generation-brief.md의 EXT-IMG-05B와 docs/extension-requirements.md의 EXT-05-02를 참고해
이력서 관리 화면의 빈 상태용 투명 배경 픽셀 장식 이미지를 제작해 줘.
빈 문서와 연필을 단순하게 그리되 실제 이력서 내용·개인정보·완료 배지는 넣지 마.
기능은 아직 구현되지 않았으므로 화면 코드에 연결하지 말고 시안만 보여줘.
```

## 7. 이미지 채택 전 확인

1. 지정한 에셋 ID의 목적과 실제 화면 위치에 맞는가? 새 디자인 묶음 안에서 일관되는가?
2. 참고 이미지의 **스타일**만 사용했고 예시 데이터·메뉴·기능을 복사하지 않았는가?
3. 작은 표시 크기와 Mobile 잘림에서 핵심 실루엣이 남는가? 투명 배경 요청이면 실제 알파가 있는가?
4. 텍스트·버튼·상태·차트와 겹치지 않고 정보 가독성을 해치지 않는가?
5. 같은 캐릭터·에셋 묶음 안에서 비율, 윤곽, 팔레트가 일관되는가?
6. 확장 전용 이미지라면 해당 기능이 구현·노출될 때까지 화면에 쓰지 않는가?

채택한 이미지는 `frontend/src/assets/redesign/`에 저장하고 최종 사용 화면에서 Desktop·Tablet·Mobile로 확인한다. 이후 이 새 이미지 묶음의 파일 경로·표시 크기·접근성 설명을 문서에 기록한다. 실제 생성·편집 작업에서는 이미지 제작 도구의 규칙을 따르되, 이 문서의 제품 범위와 데이터 의미를 우선 적용한다.

## 8. DEVJOB 로고

새싹·가방·꽃을 결합한 독자적 픽셀 심벌과 `DEVJOB` 가로형 로고를 생성했다. 심벌은 `brand-devjob-symbol.png`, 짙은 글자의 가로형은 `brand-devjob-wordmark-dark.png`다. 둘 다 투명 배경이다. 가로형은 **밝은 로그인·헤더 영역**, 심벌은 작은 공간이나 짙은 사이드바에 사용한다. 짙은 사이드바에서 글자를 함께 표시할 때는 심벌 이미지 옆에 실제 `DEVJOB` 텍스트를 밝은 CSS 색으로 렌더링한다. 시험한 밝은 글자 래스터 버전은 가장자리 잡티가 있어 채택하지 않았다.
