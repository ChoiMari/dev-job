## S06 · 프로젝트 기술의 독립성과 관계 교체 검증 (2026-10-06)

- 결정과 Trade-off: 프로젝트 기술은 기존 표준 Skill ID를 참조하되 UserSkill을 자동 생성하지 않는다. 수정은 유지할 관계를 남기고 제거·추가할 관계만 반영해 `(project_id, skill_id)` 유일 키를 같은 flush에서 다시 삽입하는 충돌을 피한다. 수정·삭제는 프로젝트 행 잠금을 사용하고, 삭제는 해당 ProjectSkill과 Project만 같은 트랜잭션에서 제거한다. 공통 Skill·SkillAlias·UserSkill은 보존한다. 페이지 조회와 기술 관계 조회를 나눠 컬렉션 fetch join으로 페이지 건수가 왜곡되는 것을 피했다.
- 구현·문제 해결 근거: 실제 PostgreSQL 테스트에서 사용자 관계의 `findByUserId`가 DTO용 getter를 엔티티 필드로 해석해 목록 `500`을 반환했다. 명시적 관계 경로 `findByUser_Id`로 고쳐 사용자별 빈 목록·페이지 조회 회귀를 통과했다. 브라우저 페이지 이동 검사에서 새 페이지 번호와 이전 20개 결과가 잠깐 함께 표시되는 문제를 확인하고 페이지가 다른 결과를 숨기며 재조회 시 이전 결과를 비우도록 수정했다. 20+1 페이지와 두 번째 페이지 오류·재시도 검사가 통과했다.
- 검증 근거: 격리 PostgreSQL 17.11 tmpfs 컨테이너의 새 `devjob_s06_test`에서 Flyway V1~V5와 JPA validate를 확인했다. S06 DB 테스트 7개는 CRUD·중복 기술 ID의 단일 관계·유지/제거/재추가·타인 상세/수정/삭제 403·없는 기술 수정의 기존 데이터 보존·페이지/ID 경계·DB 날짜/유일성/FK 제약을 확인했다. 기존 인증 등 9개와 합계 16개가 통과했고 DB 이름이 다른 26개는 제외했다. 별도 새 `devjob_s05_test`에서 V1~V5 적용 후 기존 기술 정규화·보유 관계·동시성 회귀 6개가 모두 통과했다. 기존 S05 V3 이력 DB와 개발 DB는 사용하지 않았다.

## S08 · 저장 원문 조회와 입력·페이지 경계 (2026-10-06)

- 검증 근거: Backend `build`와 일반 테스트 45개, 일회용 PostgreSQL 17의 `devjob_s08_test`에서 S08 검색/부분·정확 필터/특수 검색 문자/페이지/날짜 null·동률 정렬/원문/404/인증 테스트 7개와 기존 DB 회귀 9개가 통과했다. S08 테스트는 DB 이름 검사와 트랜잭션 rollback을 사용한다. S07 전용 테스트 8개는 DB 이름 조건으로 건너뛰었으며 이번 작업에서 재실행한 것으로 취급하지 않는다.

- 측정·회귀: 공유 토큰의 본문/흰 배경 대비 14.70:1, 설명/흰 배경 6.55:1, 주요 버튼 7.85:1, 성공/민트 6.36:1, 오류/핑크 6.21:1, 입력 경계/흰 배경 3.38:1을 색상값으로 계산했다. `pnpm build`와 기존 API·인증 테스트 19개가 통과했다. 인증/API 소스는 변경하지 않았으며 실제 Backend 연동·실물 모바일 기기·다른 브라우저 검증은 이번 UI 단계에서 재실행하지 않았다.

## S03 · 쿠키 세션의 서버 무효화와 CSRF 경계 (2026-10-05)

- 결정: 사용자가 서버 세션 + HttpOnly 쿠키를 선택했다. 로그인 응답 JSON을 유지하고 서버에서 즉시 로그아웃을 반영하는 대신, CSRF 보호·같은 출처 제공을 요구하고 서버 재시작 시 로그인 상태가 사라지는 trade-off를 수용했다. 별도 토큰 폐기 DB·세션 공유 서비스는 추가하지 않았다.
- 검증 근거: `AuthHttpTest`는 실제 Tomcat·PostgreSQL에서 로그인 전 쿠키 재사용 `401`, 로그인 전 CSRF 토큰 재사용 `403`, 로그아웃 후 인증 쿠키 재사용 `401`을 확인한다. HttpOnly·Secure·SameSite=Lax 속성도 검사한다. `AuthDatabaseTest`는 두 사용자 세션에서 입력 ID로 다른 계정을 선택할 수 없고 한 계정의 로그아웃이 다른 세션을 종료하지 않음을 확인한다.
- 입력 경계: BCrypt의 72바이트 한계를 고려해 문자 수 검사에 UTF-8 바이트 검사를 추가했다. `AuthSecurityTest`에서 25개 한글 문자(75바이트)의 가입 요청을 `400`으로 차단했고 `AuthServiceTest`에서 정확히 72바이트는 해시·대조 가능하고 73바이트는 검증에서 거부되는 것을 확인한다. 비밀번호·해시는 API와 세션 주체에 포함하지 않는다.
- 브라우저 근거: 별도 검증 DB에서 가입 완료, 잘못된 비밀번호 오류, 정상 로그인, 새로고침 후 유지, 로그아웃, 보호 경로 재접근 시 로그인 화면 이동을 직접 확인했다. 배포 HTTPS와 30분 실시간 만료 대기는 실행하지 않았다.

## 2026-10-05 · S07 채용공고 모의 수집의 실패 격리와 중복 처리

- 검증 근거: 동시에 같은 공고를 수집한 두 실행에서 생성 1건·중복 1건, 공고·회사·출처 각각 1건을 확인했다. 반복 수집은 기존 원문·회사 연결·시각을 보존하고, 다른 출처의 같은 외부 ID는 별도 공고로 저장됐다.
