# DevJob 확장 기능 프론트 UI 구현 명세

상태: B01~B03 화면 구현, 다른 확장은 설계 초안 · 기준: [확장 기능 요구사항](extension-requirements.md) (2026-10-08)

## 1. 목적과 적용 범위

이 문서는 `extension-requirements.md`의 기능을 화면에 연결할 때 필요한 **배치, 사용자 행동, 표시 상태, 접근성, 화면 검증 기준**을 정의한다. 요구사항에서 미정으로 남긴 정책은 이 문서에서도 미정으로 둔다. B01~B03 화면은 검증된 Backend 계약에 연결했으며, 나머지 화면은 [Backend 로드맵](extension-backend-roadmap.md)과 확정된 [확장 API 명세](extension-api-spec.md)를 기준으로 단계별로 연결한다.

현재 화면 기준은 [기존 UI 명세](ui-spec.md)와 `frontend/src` 구현이다. 인증 후 해시 경로, `Layout`의 Header·Sidebar, `LoadingState`·`EmptyState`·`ErrorState`·`SuccessState`, 색상 토큰과 반응형 배치를 재사용한다. 새 기능을 추가해도 기존 공고·관심공고·지원·프로필 흐름은 유지한다. 확장 화면의 새 장식 이미지는 [이미지 제작 가이드](image-generation-brief.md)에 따라 전용 폴더에서 제작한다.

## 2. 공통 화면 규칙

| ID | UI 요구사항 | 확인 방법 |

| UI-C02 | 조회 화면은 로딩·데이터 없음·조회 오류를 서로 다르게 표시한다. | 빈 결과에 오류 문구를 쓰지 않고, 오류에는 재시도 수단을 둔다. |
| UI-C03 | 저장·완료·삭제 등 변경 행동은 진행 중 중복 입력을 막고 성공·실패를 명확히 알린다. | 실패 시 사용자가 입력한 값이 유지되고, 성공 뒤 표시값이 저장 결과와 일치한다. |

| UI-C05 | 사용자 정보와 분석 결과는 서버 응답을 확인한 뒤 표시한다. | 임시 예시 수치·가짜 성공·클라이언트만의 완료 상태를 실제 저장값처럼 표시하지 않는다. |
| UI-C06 | 상태는 색상만으로 전달하지 않는다. | 텍스트·아이콘·배지를 함께 사용하고 키보드로 모든 행동이 가능하다. |
| UI-C07 | 외부 AI·채용 출처 실패는 해당 영역에 표시한다. | 외부 장애 중에도 기존 CRM 화면과 저장 기록에 접근할 수 있다. |
| UI-C08 | 작은 화면에서도 핵심 입력과 행동을 사용할 수 있어야 한다. | 1440px, 768px, 390px, 320px 폭에서 가로 넘침과 가려진 주요 행동을 확인한다. |

기존 `ui-spec.md` 6.6절을 따라 버튼·입력·메뉴 링크의 높이는 최소 44px로 하고 키보드 포커스를 눈에 띄게 표시한다. 긴 기업명·기술명·이메일·오류 문구는 줄바꿈한다. 아이콘과 캐릭터는 정보나 수치의 유일한 전달 수단으로 사용하지 않는다. 동작이 있는 꾸미기·성장 표현은 모션 감소 설정에서 줄이거나 멈추되 결과 문구는 유지한다.

## 4. 화면별 상세

### UI-E01 설정 — EXT-01

- **기본 배치:** 기존 계정 이메일·로그아웃·관리 화면 링크를 유지한다. 기능을 선택해 구현할 때 보안, 알림, 계정 삭제 영역을 별도 카드로 둔다.
- **B01 비밀번호 변경 구현:** 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 입력을 제공한다. 확인 불일치·8자 미만·UTF-8 72바이트 초과·현재와 같은 값은 제출 전에 알려준다. 확인값은 API로 보내지 않는다. 제출 중 입력·버튼을 비활성화하고 성공 뒤 값을 비운다. 서버 `204` 뒤 인증 상태를 지우고 로그인 화면으로 이동해 새 비밀번호 로그인을 안내한다. `400`은 입력 확인, `403`은 CSRF 확인 안내를 표시한다. `401`은 `GET /api/auth/me`로 세션을 확인해 현재 비밀번호 오류면 설정 화면을 유지하고, 세션 만료면 로그인 화면으로 이동한다. 비밀번호 원문은 성공·오류 문구에 표시하지 않는다.
- **계정 삭제:** 삭제 영향과 되돌릴 수 있는지 여부를 읽을 수 있게 보여준다. 현재 로그인한 계정을 삭제한다는 명시적 확인 행동을 둔다. 실패 시 로그인 상태와 기존 화면을 유지하고 이유를 안내한다. 성공 뒤에는 계정 보호 화면에 다시 들어갈 수 없게 한다.
- **알림 설정:** 제공하기로 확정된 종류·전달 방식만 선택지로 표시한다. 저장 여부를 보여주며 발송 기능이 없는 채널을 활성 선택지로 표시하지 않는다.
- **상태:** 현재 정보 로딩/오류, 입력 오류, 저장 중/성공/실패, 삭제 취소/실패를 구분한다. 계정 삭제 세부 문구는 해당 단계에서 확정한다.

### UI-E02 내 기술 — EXT-02

- `#/profile`의 기존 기술 검색·추가·삭제를 유지하고 각 보유 기술 옆에 숙련도·경험 요약과 수정·저장·취소를 배치한다. 숙련도는 화면에서 `입문`·`초급`·`중급`·`숙련`·`고급`으로 표시하고 선택한다. API의 `proficiencyLevel` 숫자 1~5와 각각 순서대로 대응하며 숫자 척도 자체를 화면에 표시하지 않는다. 경험은 0~600개월로 입력한다.
- 미입력은 `정보 없음` 등 중립 문구로 표시한다. 수치 `0`이나 최저 단계로 바꿔 보이지 않는다. 저장 후 기술 카드의 값과 편집 폼이 일치해야 한다.
- 기술 삭제 전에 추가 정보가 함께 제거되거나 보존되는 정책을 안내한다. 다른 기술의 입력값은 기술 검색·추가·삭제 과정에서 사라지지 않아야 한다.
- **상태:** 기술 목록 로딩·빈 상태·오류, 개별 기술 저장 중·검증 오류·성공을 구분한다. 숙련도는 기존 select 입력, 경험은 개월 수 입력을 사용하며 빈 선택·입력은 API에 `null`로 보낸다.

### UI-E03 개인 할 일 — EXT-03

- Sidebar `내 할 일`에서 `#/todos`로 이동한다. 목록은 미완료·완료·전체 필터와 20건 페이지를 제공하며 제목, 기한, 완료 여부를 표시한다. 등록은 `#/todos/new`, 상세·수정·완료 취소·삭제는 `#/todos/{id}`에서 처리한다.
- 대시보드의 `지원에서 나온 다음 행동`은 지원 상세 링크로, `내가 등록한 할 일`은 개인 할 일 상세 링크로 구분한다. 대시보드 개인 목록은 서버의 미완료 상위 5건을 그대로 표시한다.
- 기한 입력은 기기 현지 날짜·시각을 IANA 시간대와 오프셋으로 전송한다. 상세에는 저장된 기한의 시간대를 명시한다. 수정 폼에서는 기기 시간대로 보여주며 기한을 바꾸지 않으면 원래 시각·시간대를 보존한다. 기한을 바꾸면 현재 기기 시간대로 저장됨을 안내한다.
- 등록·수정·완료 뒤 서버 값을 다시 조회하거나 목록을 다시 불러온다. 변경 중 중복 입력을 막고 실패 시 이전 표시와 입력을 유지한다. 삭제는 대상과 숨김 결과를 확인한 뒤 실행한다. 로딩·빈 결과·조회 실패·재시도·필드 오류·변경 실패·403/404 상태를 구분한다.

### UI-E04 채용시장 분석 — EXT-04

- 기존 기술 수요 화면의 기간·직무 필터와 표본 안내를 유지한다. 확장 통계는 **경력 분포 / 지역 분포 / 기술 추이**를 제목이 있는 구역 또는 탭으로 분리한다.
- 모든 차트 옆에 동일한 정보를 텍스트·표 형태로 읽을 수 있게 한다. 경력·지역의 `미상` 처리, 각 구간의 건수·비율, 기술 추이의 기간별 표본 수를 함께 표시한다.
- 필터 변경 시 그 필터가 어느 통계에 적용됐는지 알 수 있게 한다. 기간 역전과 형식 오류를 안내하고 이전 결과를 새 결과인 것처럼 유지하지 않는다.
- **상태:** 통계별 로딩·빈 결과·조회 실패·재시도, 표본 부족, 값이 없는 구간을 구분한다. 비율은 집계 기준이 확정되기 전까지 임의 계산하지 않는다.

### UI-E05A 기업 관리 — EXT-05-01

- 독립 화면을 선택하면 관심 기업 목록, 기업 상세, 사용자 메모·관리 상태의 등록·수정·삭제 진입점을 제공한다. 공고의 회사로 이동할 수 있다면 같은 기업으로 판단한 근거와 연결 상태를 보여준다.
- 동명 기업은 이름만 같다고 같은 항목으로 합치지 않는다. 사용자가 만든 관심 기업 기록과 수집 공고의 회사 정보를 구분한다.
- **상태:** 목록 없음, 상세 없음, 연결할 공고 없음, 입력 오류, 저장·삭제 실패를 제공한다. 기업 식별·연결 정책을 확정한 뒤 검색/중복 안내를 정한다.

### UI-E05B 이력서 관리 — EXT-05-02

- 선택한 입력 방식에 맞춰 이력서 목록, 버전별 제목·수정 시각, 내용 확인·수정·삭제를 제공한다. 여러 버전이 있으면 현재 선택한 버전을 명확히 표시한다.
- 파일 방식을 도입한 경우 허용 형식·크기·업로드 진행·실패를 표시한다. 텍스트 방식이라면 저장 전 입력 검증과 긴 내용의 읽기 편한 표시를 제공한다.
- 삭제할 버전을 명시해 확인하고 다른 버전은 유지한다. 민감한 내용은 미리보기·오류에 불필요하게 노출하지 않는다.
- **상태:** 이력서 없음, 버전 없음, 조회/저장/업로드 실패, 삭제 취소, 변경 후 분석 결과가 오래된 상태를 구분한다.

### UI-E05C 면접 일정 — EXT-05-03

- 확정된 배치에서 일정의 날짜·시간대, 연결된 지원 건(있는 경우), 진행/취소 여부를 볼 수 있게 한다. 지원 상세에서 일정으로 이동한다면 어느 지원 건의 일정인지 표시한다.
- 기존 지원 건의 `다음 일정`과 독립 면접 일정의 관계가 정해지기 전에는 같은 일정을 중복 등록하거나 서로 다른 값을 같은 것으로 표시하지 않는다.
- 등록·변경·취소에는 대상 일정을 확인할 수 있는 제목과 결과 안내를 제공한다. 지난 일정과 예정 일정을 구분한다.
- **상태:** 예정 일정 없음, 잘못된 날짜·시간, 지원 건 없음, 일정 충돌(정책이 있는 경우), 저장/취소 실패를 제공한다.

### UI-E05D 학습 관리 — EXT-05-04

- Skill Gap의 `부족 기술 추천`은 분석 결과로 표시하고, 사용자가 만든 `학습 목표`와 구분한다. 목표에는 확정된 범위의 진행 상태와 완료 행동을 제공한다.
- 부족 기술에서 학습 목표를 시작할 수 있다면 기술 연결 여부를 보여주고, Skill Gap 결과가 바뀌어도 기존 학습 기록을 임의 삭제하지 않는다.
- **상태:** 추천 결과 없음, 목표 없음, 저장 중·오류, 완료 실패를 구분한다. 학습 완료가 기술 보유로 자동 전환되는지는 정책 확정 전까지 표시하지 않는다.

### UI-E06 내 캐릭터 — EXT-06

- 현재 `#/character`의 정적 안내에서 확정된 범위만 확장한다. 상태 조회가 구현되면 캐릭터 미리보기와 현재 선택 항목을 같은 화면에서 확인한다.
- 꾸미기에는 분류별 선택 목록, 현재 장착, 사용 가능/불가를 텍스트로 구분한다. 선택 후 미리보기와 저장 완료 상태가 일치해야 한다.
- 성장 기능을 도입하면 레벨·현재 EXP·다음 기준과 실제 활동에 따른 변화 이유를 보여준다. 저장 전 임의 상승 애니메이션이나 임시 보상을 실제 결과처럼 표시하지 않는다.
- **상태:** 초기 상태, 항목 없음, 장착 실패, 성장 데이터 없음, 보상 수령 실패를 구분한다. 보상·퀘스트는 해당 요구사항이 확정된 뒤 별도 화면 요소로 추가한다.

### UI-E07 새 채용 출처 — EXT-07

- 새 공식 출처가 확정되면 기존 `#/jobs`의 출처 필터·카드·상세에 출처명과 제공 가능한 정보를 반영한다. 정보가 없는 필드는 `정보 없음` 등으로 표시하고 다른 출처의 값으로 채우지 않는다.
- 외부 원문 링크의 성격(실제 공고/기관 홈페이지 등)을 정확히 안내한다. 새 출처만의 상세 정보가 있다면 해당 공고에서만 별도 구역을 표시한다.
- 수집 실행 UI는 **사용자 실행 방식이 확정된 경우에만** 추가한다. 현재 공고 목록은 저장된 결과 탐색 화면이다.
- **상태:** 새 출처의 공고 없음, 필터 결과 없음, 일부 정보 누락, 원문 링크 없음, 외부 수집 실패를 구분한다. 수집 실패는 기존 저장 공고 목록을 가리지 않는다.

### UI-E08 문서 분석·새 추천 — EXT-08

- 이력서·자기소개서 분석 API가 확정되면 사용자가 어떤 문서를 분석하는지 확인하고 명시적으로 요청하게 한다. 문서 내용과 분석 결과의 연결·최신 여부를 표시한다.
- 결과 화면은 진행 중·완료·실패를 구분한다. 실패 시 원인을 과도하게 노출하지 않으면서 재시도 행동을 제공한다. 입력이 바뀌면 이전 결과를 최신 결과처럼 표시하지 않는다.
- 의미 기반 비교·추천 API가 확정되면 기존 기술 일치도와 제목·설명·근거를 구분한다. `합격 확률`이라는 표현을 쓰지 않는다.
- **상태:** 분석할 문서 없음, 진행 중, 결과 없음, 실패, 오래된 결과, 재시도 중을 제공한다. 결과 항목과 표현은 분석 목적·검증 기준이 정해진 뒤 확정한다.

## 5. 요구사항 연결과 화면 검증

| 요구사항 | 화면 검증 시나리오 |
| --- | --- |
| COM-01, EXT-01 | 로그인 사용자만 설정에 접근하고 계정 변경/삭제 후 보호 화면 상태가 일치한다. |
| EXT-02 | 기술 추가→값 입력→새로고침→수정→기술 삭제 흐름에서 값과 미입력 표시가 일관된다. |
| EXT-03 | 할 일 등록→수정→완료→재조회→삭제에서 대시보드 다음 행동과 구분된다. |
| EXT-04 | 필터 적용·해제, 빈 기간, 표본 부족, 미상 값에서 차트와 텍스트 수치가 일치한다. |
| EXT-05-01~04 | 각 관리 기록의 등록→재조회→변경→취소/삭제와 기존 공고·지원·Skill Gap과의 구분을 확인한다. |

| EXT-07 | 출처별 필터·상세·원문 안내와 한 출처 장애 중 기존 공고 탐색을 확인한다. |

각 기능의 UI 구현 후에는 해당 시나리오를 키보드와 Desktop·Tablet·Mobile 폭에서 확인한다. 접근성 문구, 빈 상태, 오류 재시도, 저장 후 재조회가 빠지지 않았는지 점검한다. 아직 선택하지 않은 기능의 화면 검증은 완료로 보고하지 않는다.
